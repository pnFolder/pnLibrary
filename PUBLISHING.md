# Publishing pnLibrary API to Maven Central

Only `pnlibrary-api` is published as a developer dependency. Platform runtime JARs (Bukkit/Bungee/Velocity) remain GitHub Release assets.

Published coordinates:

```text
io.github.overdyn:pnlibrary-api:<version>
```

## One-time Maven Central setup

1. Sign in to https://central.sonatype.com with the GitHub account `overdyn`.
2. Verify that the namespace `io.github.overdyn` is present and verified.
3. In Central Portal -> Account, generate a **User Token**. Save its generated username and password.
4. Create a GPG key if you do not already have one:

```bash
gpg --full-generate-key
```

5. Find the key id:

```bash
gpg --list-secret-keys --keyid-format=long
```

6. Publish the public key to a public keyserver supported by Maven Central. For example, after choosing a supported keyserver:

```bash
gpg --keyserver <supported-keyserver> --send-keys <KEY_ID>
```

7. Export the private key for GitHub Actions:

```bash
gpg --export-secret-keys --armor <KEY_ID>
```

Copy the complete `-----BEGIN PGP PRIVATE KEY BLOCK-----` ... `-----END PGP PRIVATE KEY BLOCK-----` value.

## GitHub Actions secrets

Repository -> Settings -> Secrets and variables -> Actions -> Secrets -> New repository secret.

Create:

- `MAVEN_CENTRAL_USERNAME` — username generated by the Central Portal User Token.
- `MAVEN_CENTRAL_PASSWORD` — password generated by the Central Portal User Token.
- `SIGNING_KEY` — complete ASCII-armored private GPG key.
- `SIGNING_PASSWORD` — GPG key password. It may be empty if the key has no password.

Do not commit these values to the repository.

## GitHub Actions variables

Repository -> Settings -> Secrets and variables -> Actions -> Variables.

Maven Central requires explicit license metadata. Choose the project's license before the first public Central release, then create:

- `MAVEN_LICENSE_NAME` — for example `Apache-2.0` or `MIT` (use the license actually chosen for the project).
- `MAVEN_LICENSE_URL` — the canonical URL for that license.

The build intentionally does not choose a software license automatically on behalf of the project owner.

## Publish from GitHub

The workflow `.github/workflows/publish-maven-central.yml` runs:

- manually via Actions -> `Publish pnLibrary API to Maven Central` -> Run workflow;
- automatically whenever a GitHub Release is published.

It runs:

```bash
./gradlew --no-daemon :pnlibrary-api:publishAndReleaseToMavenCentral
```

The workflow uploads, validates, and releases the deployment through the Central Portal.

## Publish from a local computer

The same Gradle properties can be placed in `~/.gradle/gradle.properties`:

```properties
mavenCentralUsername=<central-token-username>
mavenCentralPassword=<central-token-password>
signingInMemoryKey=<ascii-armored-private-key>
signingInMemoryKeyPassword=<gpg-password>
POM_LICENSE_NAME=<chosen-license-name>
POM_LICENSE_URL=<chosen-license-url>
POM_LICENSE_DIST=repo
```

For a multiline private key, environment variables are usually easier than `gradle.properties`.

Windows PowerShell example:

```powershell
$env:ORG_GRADLE_PROJECT_mavenCentralUsername="..."
$env:ORG_GRADLE_PROJECT_mavenCentralPassword="..."
$env:ORG_GRADLE_PROJECT_signingInMemoryKey=Get-Content -Raw .\private-key.asc
$env:ORG_GRADLE_PROJECT_signingInMemoryKeyPassword="..."
$env:ORG_GRADLE_PROJECT_POM_LICENSE_NAME="..."
$env:ORG_GRADLE_PROJECT_POM_LICENSE_URL="..."
$env:ORG_GRADLE_PROJECT_POM_LICENSE_DIST="repo"
.\gradlew.bat :pnlibrary-api:publishAndReleaseToMavenCentral
```

## Consuming pnLibrary API

After Maven Central has synced the release:

```kotlin
repositories {
    mavenCentral()
}

dependencies {
    compileOnly("io.github.overdyn:pnlibrary-api:2.0.0-beta.4")
}
```

Do not shade/relocate `pnlibrary-api`; the installed pnLibrary runtime provides the API at runtime.
