# pnLibrary — личный чек-лист проекта

Этот файл предназначен для ручной проверки проекта перед релизом. Здесь описано не устройство классов, а то, что пользователь и разработчик должны увидеть в работе.

Обозначения:

- `[ ]` — ещё не проверено;
- `[x]` — проверено и работает;
- `[!]` — обнаружена проблема, её нужно записать в разделе «Проблемы».

## 1. Базовая сборка

- [ ] Проект клонируется/открывается без ошибок Gradle.
- [ ] `./gradlew test` завершается успешно.
- [ ] Собираются все нужные артефакты библиотеки.
- [ ] В опубликованные JAR не попадают тестовые классы и временные файлы.
- [ ] Версия проекта одинаково указана в артефактах, документации и release-файле.
- [ ] Проект собирается на Java 8, если модуль заявляет совместимость с Java 8.
- [ ] Отдельно проверена сборка на актуальной Java (17/21).

## 2. Подключение библиотеки к плагину

- [ ] Плагин подключает только необходимые модули, а не весь проект целиком.
- [ ] Плагин запускается без `ClassNotFoundException` и `NoSuchMethodError`.
- [ ] Инициализация библиотеки выполняется один раз.
- [ ] Повторная инициализация не создаёт дубликаты регистраций, задач и слушателей.
- [ ] При выключении плагина фоновые задачи останавливаются.
- [ ] Ошибка настройки выводится понятным сообщением и не оставляет сломанное состояние.

## 3. Плагин и модули

- [ ] Основной плагин регистрируется в реестре.
- [ ] Для одного плагина можно зарегистрировать несколько модулей.
- [ ] Модули одного плагина видят общий контекст плагина.
- [ ] Модули не получают контекст другого плагина.
- [ ] Повторное имя модуля отклоняется понятной ошибкой.
- [ ] Модуль можно получить по имени.
- [ ] Получение незарегистрированного модуля возвращает предсказуемый результат.
- [ ] Старые/deprecated-методы не используются в новом API.
- [ ] Контекст и жизненный цикл плагина корректно закрываются при отключении.

## 4. Контекст Bukkit-сервера

- [ ] Из контекста доступна исходная строка версии сервера.
- [ ] Из контекста доступна известная версия `MinecraftVersion`.
- [ ] Для неизвестной версии возвращается `UNKNOWN`, но исходная строка не теряется.
- [ ] Для неизвестной числовой версии доступны её `major`, `minor`, `patch`.
- [ ] Из единого `serverInfo()` доступна платформа сервера.
- [ ] Для Paper/Purpur/Folia/Spigot определяется базовый тип, если он распознан.
- [ ] Для неизвестного форка возвращается `UNKNOWN`, но его настоящее имя доступно.
- [ ] `platformName()` возвращает имя без потери исходного написания.
- [ ] `platformKey()` возвращает стабильное имя в нормализованном виде.
- [ ] Проверка платформы не зависит от регистра, пробелов, дефисов и подчёркиваний.
- [ ] Проверка версии не падает на нестандартной строке ядра.

## 5. Диагностика

- [ ] Пользователь может включить диагностику настройкой плагина.
- [ ] Диагностика создаёт понятный снимок состояния.
- [ ] В снимке указаны версия плагина, версия библиотеки и серверная платформа.
- [ ] В снимке не выводятся пароли, токены и приватные данные.
- [ ] Диагностика учитывает все зарегистрированные модули.
- [ ] Ошибка одного модуля не ломает диагностику остальных.
- [ ] Пользователь получает понятный путь/ссылку на результат диагностики.
- [ ] Команда диагностики работает после перезапуска сервера.

## 6. Обновления

- [ ] Канал обновлений выбирается отдельно (`stable`, `beta`, `dev` и т. п.).
- [ ] Автоматическая загрузка может быть включена и выключена.
- [ ] При выключенной загрузке библиотека только сообщает о доступном обновлении.
- [ ] При включённой загрузке скачивается подходящий артефакт для текущей платформы.
- [ ] Проверяется совместимость API библиотеки.
- [ ] Проверяется совместимость платформы и версии Java.
- [ ] Ошибка сети не ломает запуск плагина.
- [ ] Повторная проверка через заданный интервал не создаёт параллельные загрузки.
- [ ] Список релизов кэшируется и корректно обновляется.
- [ ] Неизвестный или повреждённый release-файл обрабатывается безопасно.

## 7. Release-файл и артефакты

- [ ] При сборке автоматически создаётся release-файл.
- [ ] В нём есть название продукта.
- [ ] Указана версия продукта.
- [ ] Указан канал релиза.
- [ ] Указан совместимый API pnLibrary.
- [ ] Для каждого артефакта указана платформа.
- [ ] Указаны минимальная и максимальная версии платформы.
- [ ] Указаны минимальная и максимальная версии Java.
- [ ] Указан размер файла.
- [ ] Указан hash файла.
- [ ] Имя артефакта в release-файле совпадает с реально опубликованным файлом.
- [ ] Зависимости в release-файле соответствуют зависимостям, описанным в плагине.

## 8. Зависимости плагинов

- [ ] Обязательная зависимость блокирует запуск при отсутствии.
- [ ] Необязательная зависимость не блокирует запуск.
- [ ] Для зависимости можно указать минимальную версию.
- [ ] Можно указать репозиторий и конкретную версию/ветку.
- [ ] Автоматическая загрузка зависимости реально управляется настройкой.
- [ ] При ручном режиме пользователь получает понятное уведомление.
- [ ] Дубликаты зависимостей обнаруживаются до запуска.
- [ ] Циклические зависимости обнаруживаются и не приводят к бесконечной загрузке.
- [ ] Старые плагины можно указать по прямой ссылке на конкретную версию.

## 9. Удалённая политика/проверка

- [ ] Проверка запускается при старте плагина.
- [ ] Проверка запускается повторно через заданный интервал.
- [ ] Источник можно задать прямой ссылкой.
- [ ] Ошибка скачивания обрабатывается без падения сервера.
- [ ] Проверка получает версию плагина, версию Minecraft и данные сервера.
- [ ] Проверка получает платформу и её исходное имя.
- [ ] Результат `ALLOW` оставляет плагин включённым.
- [ ] Результат `DENY` останавливает именно проверяемый плагин.
- [ ] При `DENY` в консоли объясняется причина и дальнейшее действие.
- [ ] Удалённый код не получает лишние секреты и произвольный доступ без явного решения.
- [ ] Проверена несовместимость байткода с Java 8/17/21.
- [ ] Ошибка компиляции/загрузки удалённой политики приводит к безопасному результату.

## 10. Console/UI

- [ ] Сообщения запуска оформлены единообразно.
- [ ] Успешная инициализация заметна в консоли.
- [ ] Предупреждения и ошибки визуально различаются.
- [ ] Сообщения не содержат лишних stack trace в обычном режиме.
- [ ] Подробный stack trace можно включить отдельно.
- [ ] Текст корректно отображается в Windows-консоли и Linux-консоли.
