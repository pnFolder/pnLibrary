# Правила для нейросети: плагин на pnLibrary

Скопируйте этот файл в корень репозитория плагина (под именем `AGENTS.md` или как инструкцию для вашего ИИ-помощника).
Подробности и поля: https://github.com/pnFolder/pnLibrary/blob/main/docs/repository.md

## Что обязательно

- Использовать только пакет `org.pnfolder.pnlibrary.api`. Классы `core`, `runtime` и `platforms` не импортировать.
- Зависимость `compileOnly("io.github.pnfolder:pnlibrary-api:<версия>")`; библиотека не упаковывается в плагин.
- В `plugin.yml`: `depend: [pnLibrary]`.
- Получать библиотеку через `PnLibraryProvider.get()` и регистрировать плагин через `plugins.register(this)`.
- Держать в корне репозитория папку `.pnlibrary` с `releases.json` и `changelogs/<версия>.md`.
- При каждом выпуске менять оба: запись в `releases.json` и файл описания той же версии.

## Правила `releases.json`

- `schema` всегда `1`; `product` совпадает с id продукта плагина.
- Версия по semver, не повторяется; тег релиза на GitHub `v<версия>`.
- Канал: `stable`, `rc`, `beta`, `alpha` или `dev`. Обычные серверы получают только `stable`.
- У каждого файла: `file`, `platform` (`BUKKIT`, `BUNGEECORD`, `VELOCITY` или `UNIVERSAL`), `url` только HTTPS,
  `sha256` из 64 символов. Без `sha256` файл не примут.
- Сумму считать от настоящего файла, не придумывать.
- Записи вручную не «чинить» задним числом: опубликованную версию не перезаписывать, выпускать новую.

## Чего не делать

- Не подменять работающий JAR на ходу и не перезапускать сервер: обновление только готовится.
- Не хранить токены, пароли и ключи в репозитории и в `releases.json`.
- Не придумывать поля, которых нет в [docs/repository.md](https://github.com/pnFolder/pnLibrary/blob/main/docs/repository.md).
- Не менять публичные интерфейсы pnLibrary: они проверяются на бинарную совместимость.

## Проверка перед коммитом

1. `releases.json` — корректный JSON, версии без повторов.
2. Для каждой версии есть `changelogs/<версия>.md`.
3. Сборка и тесты плагина проходят.
