# Каталог релизов pnLibrary

## Назначение

`releases.json` — единственный внешний каталог доступных релизов продукта.
Библиотека загружает этот файл, выбирает совместимый релиз и только затем
скачивает указанный JAR.

Gradle-плагин этот файл не создаёт. Разработчик вручную добавляет запись в
репозитории после публикации JAR на GitHub.

## Расположение

Файл размещается в корне репозитория продукта:

```text
.pnlibrary/releases.json
```

Публичный адрес обычно имеет вид:

```text
https://raw.githubusercontent.com/<owner>/<repository>/<branch>/.pnlibrary/releases.json
```

## Формат

```json
{
  "schema": 1,
  "product": "pnlibrary",
  "releases": [
    {
      "version": "2.6.0",
      "channel": "stable",
      "description": "Стабильный релиз",
      "publishedAt": "2026-09-29T12:00:00Z",
      "api": {
        "minimum": 1,
        "maximum": 1
      },
      "artifacts": [
        {
          "file": "pnLibrary-2.6.0-bukkit-java8.jar",
          "platform": "BUKKIT",
          "minecraft": {
            "minimum": "1.20",
            "maximum": "1.21.11"
          },
          "java": {
            "minimum": 8,
            "maximum": 21
          },
          "url": "https://github.com/pnFolder/pnLibrary/releases/download/v2.6.0/pnLibrary-2.6.0-bukkit-java8.jar"
        }
      ]
    }
  ]
}
```

## Поля

- `schema` — версия формата каталога.
- `product` — стабильный идентификатор продукта.
- `version` — SemVer-версия релиза. Канал в неё не дублируется.
- `channel` — `stable`, `beta`, `alpha` или `dev`.
- `description` — короткое описание для логов и диагностики.
- `publishedAt` — время публикации в ISO-8601 UTC, например `2026-09-29T12:00:00Z`.
- `api` — диапазон pnLibrary API, поддерживаемый релизом.
- `artifacts` — JAR-файлы для конкретных платформ.
- `platform` — `BUKKIT`, `BUNGEECORD` или `VELOCITY`.
- `minecraft` — диапазон Minecraft только для серверных платформ, например Bukkit.
- `platformApi` — диапазон native API для прокси. Для Bukkit это поле не добавляется.
- `java` — минимальная и необязательная максимальная версия Java.
- `url` — HTTPS-ссылка на опубликованный JAR.

`size`, `sha256` и `component.json` в каталоге не используются. Размер и SHA-256
вычисляются библиотекой после скачивания. Фактическая проверка JAR выполняется
по plugin descriptor, bytecode, платформе, Java и pnLibrary API.

## Каналы

Канал задаёт допустимую зрелость релиза, а не порядок записей в массиве:

```text
STABLE → только stable
BETA   → stable + beta
ALPHA  → stable + beta + alpha
DEV    → stable + beta + alpha + dev
```

Сначала библиотека фильтрует релизы по каналу и совместимости, затем выбирает
максимальную SemVer-версию. Поэтому сотни beta/dev-релизов не мешают найти
последний стабильный релиз.

## Правила ручного добавления

1. Сначала опубликовать JAR в GitHub Release.
2. Проверить точное имя файла и URL.
3. Добавить запись в `releases.json`.
4. Не указывать `null` для неприменимых полей — поле нужно удалить.
5. Для прокси использовать `platformApi`, для Bukkit — `minecraft`.
6. Не переиспользовать версию для другого содержимого JAR.
7. После изменения проверить JSON и доступность каждой ссылки.

## Алгоритм библиотеки

```text
загрузить releases.json
→ проверить schema и записи
→ отфильтровать channel/API/Java/platform
→ выбрать максимальную совместимую SemVer
→ скачать JAR во временный файл
→ проверить размер и SHA-256
→ проверить plugin.yml или paper-plugin.yml
→ проверить Java bytecode
→ атомарно переместить JAR в update/
```

При ошибке каталога, сети или совместимости текущая установленная версия не
изменяется. Устаревший каталог можно показывать только как диагностическую
информацию, но нельзя использовать его для автоматической установки.

## Обновление зависимостей

Если обновление плагина требует pnLibrary API выше текущего, updater сначала
ищет совместимый релиз pnLibrary. Затем проверяет плагины, зарегистрированные
с этим API. Создаётся единый план обновления только тогда, когда все
обязательные компоненты совместимы. При отсутствии полного плана файлы не
изменяются и пользователю показывается причина отказа.
