# Зависимости плагина

Плагин при регистрации говорит, какие другие плагины ему нужны. pnLibrary проверяет их при запуске и, если чего-то
не хватает, либо скачивает сама, либо показывает администратору, что и откуда взять.

## Что можно указать

```kotlin
plugin.depends(
    ExternalPluginDependency.builder("Vault", "1.7.0")          // имя плагина и минимальная версия
        .title("Экономика")                                      // короткое имя для людей
        .description("Нужна для денег и магазинов.")             // зачем она нужна
        .artifact("https://example.org/Vault.jar", sha256 = "3c0e…")   // прямая ссылка и сумма издателя
        .mirror("https://mirror.example.org/Vault.jar")          // запасной адрес того же файла
        .downloadPage("https://example.org/vault")               // страница, если автоскачивание не подходит
        .required(true)                                          // false: плагин запустится и без неё
        .downloadPolicy(DownloadPolicy.AUTOMATIC)                // MANUAL | AUTOMATIC | FORCED
        .build(),
)
```

Короткая запись для простых случаев: `Dependencies.plugin("Vault", "1.7.0", "https://example.org/vault")` (страница, ручная
установка) и `Dependencies.plugin("Vault", "1.7.0", listOf("https://a.org/Vault.jar", "https://b.org/Vault.jar"))`
(несколько адресов без суммы).

| Поле | Что значит |
|---|---|
| `title`, `description` | как зависимость называется и зачем нужна: попадают в сообщение администратору |
| `required` | обязательная (по умолчанию) или нет; в сообщении они разделены |
| `artifact`, `mirror` | откуда качать: первый адрес, потом запасные по очереди, сколько угодно |
| `sha256` | сумма издателя; после скачивания считается SHA-256 файла и сверяется с ней. Суммы нет: файл берётся с первой ссылки, которая ответила, ничего не сравнивается и не запоминается |
| `maxBytes` | наибольший размер этого файла в байтах; без него действует общий потолок 512 МБ, можно и уменьшить, и увеличить (до 2 ГБ). У варианта свой `maxBytes`, у общего файла `.maxBytes(...)` в билдере |
| `downloadPolicy` | `MANUAL`: только по команде администратора; `AUTOMATIC`: самой, пока включена автозагрузка; `FORCED`: самой всегда |
| `downloadPage` | куда идти, если файл нельзя скачать автоматически |

Скачанный JAR ещё раз проверяется: имя плагина внутри и его версия должны совпасть с тем, что просили.

## Три режима скачивания

| Режим | Что значит |
|---|---|
| `MANUAL` | сами не качаем, только показываем карточку со ссылками (по умолчанию, когда нет прямой ссылки) |
| `AUTOMATIC` | качаем сами, пока администратор не выключил автозагрузку (по умолчанию, когда есть прямая ссылка) |
| `FORCED` | качаем сами, даже если автозагрузка выключена |

Задаётся одним `downloadPolicy(...)`; те же `MANUAL`, `AUTOMATIC`, `FORCED`, что у файлов (`docs/downloads.md`).

## Разные файлы для разных серверов

Если плагину нужен свой jar под платформу или версию Minecraft, добавьте варианты. У каждого свои ссылка, SHA-256
и зеркала. Берётся первый подходящий этому серверу, и проверяется только его сумма: остальные файлы не скачиваются и не
сравниваются. Общий файл (`url` или `artifact`) остаётся запасным, если ни один вариант не подошёл.

```kotlin
ExternalPluginDependency.builder("Vault", "1.7.0")
    .variant("https://example.org/Vault-legacy.jar", "ab12…", minecraftBefore = "1.20", label = "для 1.19 и старше")
    .variant("https://example.org/Vault-velocity.jar", "cd34…", platforms = setOf(PlatformType.VELOCITY))
    .variant("https://example.org/Vault-new.jar", "ef56…", minecraftFrom = "1.20", mirrors = listOf("https://mirror.example.org/Vault-new.jar"))
    .downloadPage("https://example.org/vault")
    .build()
```

| Параметр | Что значит |
|---|---|
| `platforms` | для каких платформ файл (пусто: для всех) |
| `minecraftFrom` | с какой версии Minecraft, включительно |
| `minecraftBefore` | до какой версии, не включая |
| `label` | название варианта, видно в карточке |

Версия Minecraft известна только на сервере Bukkit/Paper; на прокси подходят варианты без ограничения по версии. Если ни один
вариант не подошёл, карточка пишет об этом и показывает страницу для ручной загрузки.

## Что видит администратор

Автоскачивание включено (`/pn deps auto on`, по умолчанию включено): библиотека качает файл сама, пишет в консоль, что
подготовлено, а плагины загружаются при следующем запуске. Сервер сама не перезапускает.

Выключено, или у зависимости нет прямой ссылки: в консоль выходит карточка «НЕ ХВАТАЕТ ПЛАГИНОВ». В ней два списка,
**обязательные** и **необязательные**, у каждого плагина название, версия, описание, все ссылки и способ проверки файла.
Ниже код установки: `/pn deps install <код>` скачивает всё из этой карточки сразу, ввод кода и есть подтверждение.
`/pn deps` показывает то же самое в любой момент.

То же есть в меню: **Настройки → «Недостающие плагины»** включает и выключает автозагрузку, **«Что не хватает»** показывает группы со
ссылками и скачивает группу кликом (нужно право на настройки).

## Права

`/pn deps` и экран меню «Что не хватает» требуют право `pnlibrary.deps` (в меню: право на настройки); консоль может всё.

## Что пока не так

- Свои плагины pnFolder как зависимость (`ManagedProductDependency`) ставятся через систему обновлений, а не через карточку
  выше; сейчас она их сама не доустанавливает (`allowNewPlugins` выключен), блокируя обновление с причиной
  «нужен такой-то продукт».
- Зеркала одного файла делят одну сумму; для разных файлов используйте варианты.
