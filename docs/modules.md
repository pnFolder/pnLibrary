# Модули плагина: включить, выключить, перезапустить

Плагин делится на модули (`registration.registerModule(...)`). Если модуль зарегистрирован вместе с `PluginModule`,
администратор может переключать его командами и в меню, не перезапуская сервер.

```kotlin
class Shop : PluginModule {
    override fun onEnable(context: ModuleContext) {
        context.registerCommand("shop") { /* ... */ }
    }
    override fun onDisable(context: ModuleContext) { /* закрыть то, что открыл сам */ }
    override fun onReload(context: ModuleContext): Boolean {
        // перечитать настройки на месте; false значит «не умею», тогда модуль перезапустится
        return false
    }
}

registration.registerModule("shop", Shop())
```

Методы пустые по умолчанию, переопределяйте нужные. При выключении библиотека сама отменяет задачи модуля и снимает его
команды. Слушатели и всё, что модуль открыл сам, закрывается в `onDisable`.

`context.control` (`ModuleControl`) даёт то же из кода: `state` (`ENABLED`, `DISABLED`, `FAILED`), `lastError`, `enable()`,
`disable()`, `restart()`, `reload()`, `autoStart`/`setAutoStart(...)`. Ошибка в методе не выбрасывается: модуль становится
`FAILED`, ошибка видна в `lastError`, команде и меню, а `enable()` пробует ещё раз. Модуль без `PluginModule` виден в списке,
но не переключается.

## Команды

| Команда | Что делает |
|---|---|
| `/pn modules` | все модули и их состояние |
| `/pn modules view <плагин:модуль>` | карточка: состояние, ошибка, автозапуск, кнопки |
| `/pn modules enable\|disable\|restart\|reload <плагин:модуль>` | переключить сейчас |
| `/pn modules auto <плагин:модуль> on\|off` | включать ли модуль вместе с сервером (сохраняется) |

Право: `pnlibrary.modules`; консоль может всегда. Вместо `плагин:модуль` можно написать просто id модуля, если он один.

## Меню

Главное меню, «Модули плагинов»: список и карточка с кнопками «Включить», «Выключить», «Перезапустить», «Перечитать»,
«Включать с сервером». В карточке плагина обновлений есть кнопка «Модули» только с его модулями. Всё, что есть в меню, есть и
командой, и наоборот.

## Что запоминается

Модули, которые администратор оставил выключенными, хранятся в `data/modules/preferences.json` (`{"disabled": [...]}`).
Такой модуль не запускается при старте сервера, пока его не включат командой или кнопкой «Включать с сервером».

## Библиотеки модуля

Модуль сам просит нужные ему Maven-библиотеки: что скачать, откуда и как проверить. Библиотека загружается через Libby
перед `onEnable`, при каждом запуске модуля; уже загруженная второй раз не скачивается.

```kotlin
class Shop : PluginModule {
    override fun libraries() = listOf(
        ModuleLibrary.builder("com.zaxxer", "HikariCP", "5.1.0")
            .source { repository("https://repo.example.org/maven2/").sha256("3c0e…64 символа") }  // другой файл отклоняется
            .build(),
        ModuleLibrary.of("org.slf4j:slf4j-api:2.0.13"),        // коротко: Maven Central
    )

    override fun onEnable(context: ModuleContext) {
        val pool = context.libraries.classLoader.loadClass("com.zaxxer.hikari.HikariDataSource")
    }
}
```

| Настройка | Смысл |
|---|---|
| `source { … }` | место, откуда можно взять jar: ссылка или репозиторий, своя сумма и имя; можно сколько угодно (см. «Откуда берётся jar») |
| `mavenCentral(false)` | не заходить в Maven Central (по умолчанию он пробуется последним) |
| `classifier(...)` | классификатор, например `shaded` |
| `scope(LibraryScope.…)` | куда загружать: `PLUGIN` (по умолчанию), `ISOLATED`, `LIBRARY` |
| `platforms(PlatformType.…)` | грузить только на этих платформах; без вызова грузится везде |
| `optional()` | модуль запустится, даже если библиотеку загрузить не удалось |

Транзитивные зависимости не подтягиваются: перечислите все нужные jar. Нужную библиотеку можно запросить и позже:
`context.libraries.load("группа:артефакт:версия")`. Не загрузилась обязательная библиотека: модуль в состоянии `FAILED`, причина
в `/pn modules view`.

### Библиотеки плагина, просмотр и удаление

Библиотеку можно зарегистрировать на весь плагин: её увидят все его модули, и она скачается один раз.

```kotlin
val registration = library.plugins.register(this)
registration.libraries.load("org.slf4j:slf4j-api:2.0.13")   // на плагин, для всех модулей
registration.registerModule("shop", Shop())                  // у Shop свои libraries()
```

| Что | Как |
|---|---|
| какие библиотеки у модуля | `context.libraries.loaded` (свои), `.available` (свои и плагина) |
| какие у плагина | `registration.libraries.loaded`; со всеми модулями: `registration.allLibraries` |
| найти по имени | `libraries.find("com.zaxxer", "HikariCP")` |
| взять класс | `libraries.loadClass("com.zaxxer.hikari.HikariDataSource")`: сначала в библиотеках модуля, потом плагина |
| убрать из списка | `libraries.remove(library)`: список очищается, повторно не грузится; сам jar из памяти не выгрузить, классы живут до перезапуска сервера |

В `/pn modules view <модуль>` перечислены библиотеки модуля и (со словами «от плагина») библиотеки его плагина; в меню
в карточке модуля видно их число.

### Куда загружается библиотека

- **`PLUGIN`** (по умолчанию): на Bukkit и BungeeCord библиотека добавляется в загрузчик плагина-владельца (того, что
  зарегистрировал модуль), так что классы видны его собственному коду. На Velocity общий загрузчик пока pnLibrary.
- **`ISOLATED`**: отдельный загрузчик на владельца, `libraries.classLoader` и `libraries.loadClass(...)`. Два модуля могут
  взять две версии одной библиотеки без конфликта; плагин видит её классы только через этот загрузчик.
- **`LIBRARY`**: загрузчик pnLibrary, классы видят все плагины с зависимостью от pnLibrary. Нужно редко: версии разных
  плагинов спорят между собой. Берите, только если плагины должны делить библиотеку намеренно.

Платформу (Bukkit, BungeeCord, Velocity) pnLibrary определяет сама: ничего менять не нужно. `platforms(...)` нужен, только
если библиотека нужна на части платформ; на остальных она тихо пропускается и не считается ошибкой.

### Откуда берётся jar

Способ один: список мест `source { … }`. Библиотека пробует их по порядку, пока одно не отдаст jar, который проходит проверку.
После всех ваших мест идёт Maven Central, если не выключен `mavenCentral(false)`. Мест можно написать сколько угодно, хоть тысячу.

Внутри блока выбирается адрес и, по желанию, сумма и имя:

| В блоке | Смысл |
|---|---|
| `link("https://…/a.jar")` | прямая ссылка на сам jar: pnLibrary просто скачивает его |
| `repository("https://…/maven2/")` | репозиторий или зеркало: pnLibrary строит путь по координатам (`группа/артефакт/версия/артефакт-версия.jar`) и качает по нему |
| `sha256("…")` | сумма jar из этого места; другой файл отвергается, пробуется следующее место |
| `name("…")` | название места для ошибок и меню; без него это хост адреса |
| `description("…")` | одно предложение, что это за место, например «основной репозиторий компании» |

Не получилось скачать, сети нет или сумма не совпала: берётся следующее место. Библиотека не загрузилась, только если не
сработало ни одно; в ошибке причина по каждому месту. Место, которое только что не сработало, остальные библиотеки пробуют последним
(пять минут, только в памяти, ничего не сохраняется): так мёртвое зеркало не задерживает каждую загрузку. Самое быстрое место по IP не
подбирается: порядок задаёте вы, самое надёжное ставьте первым. Сумма проверяется только если вы её указали, иначе jar из этого места
не проверяется, в `/pn modules libs` видно «jar не проверяется». pnLibrary ничего не запоминает сама.

### Полные примеры

```kotlin
// 1. Только координаты: Maven Central
ModuleLibrary.of("org.slf4j:slf4j-api:2.0.13")

// 2. Один репозиторий и сумма, потом Maven Central
ModuleLibrary.builder("com.zaxxer", "HikariCP", "5.1.0")
    .title("Пул соединений")                          // название самой библиотеки
    .description("Держит соединения с базой.")        // описание самой библиотеки
    .source { repository("https://repo.example.org/maven2/").sha256("3c0e…").name("Наш репозиторий").description("Основной") }
    .build()

// 3. Только прямая ссылка, больше никуда не заходить
ModuleLibrary.builder("org.example", "tool", "1.0")
    .source { link("https://cdn.example.org/tool-1.0.jar").sha256("9f2a…").name("CDN") }
    .mavenCentral(false)
    .build()

// 4. Много мест подряд, ссылки и репозитории вперемешку
ModuleLibrary.builder("com.zaxxer", "HikariCP", "5.1.0")
    .source { link("https://cdn.example.org/HikariCP-5.1.0.jar").sha256("3c0e…").name("CDN") }
    .source { repository("https://mirror.example.org/maven/").sha256("9f2a…").name("Зеркало") }  // другая сборка, другая сумма
    .source { repository("https://repo.example.org/maven2/") }                                    // без проверки
    .source { link("https://backup.example.org/hikari.jar").name("Запасная") }
    .build()                                                                                      // в конце Maven Central

// 5. Остальные настройки
ModuleLibrary.builder("net.dv8tion", "JDA", "5.0.0")
    .classifier("withDependencies")                 // jar с классификатором
    .scope(LibraryScope.ISOLATED)                   // свой загрузчик, версия не спорит с чужими
    .platforms(PlatformType.BUKKIT)                 // только на Bukkit; на остальных тихо пропускается
    .optional()                                     // модуль запустится и без неё
    .build()

// 6. Из Java, готовое место можно использовать в нескольких библиотеках
LibrarySource corp = LibrarySource.builder().repository("https://nexus.corp.example/maven/").sha256("…").name("Корп").build();
ModuleLibrary.builder("g", "a", "1").source(corp).build();
```

### Название и описание

Чтобы администраторы и игроки понимали, что это:

```kotlin
ModuleLibrary.builder("com.zaxxer", "HikariCP", "5.1.0")
    .title("Пул соединений")
    .description("Держит открытые соединения с базой, чтобы запросы шли быстрее.")
    .build()

registration.registerModule("shop", Shop()) { it.metadata { m -> m.description("Магазин: покупка и продажа предметов.") } }
```

### Вся библиотека целиком

- `library.plugins.allModules()`: все модули всех плагинов.
- `library.plugins.libraryUsage()`: все библиотеки и кто их зарегистрировал (`LibraryUsage.owner`: `плагин` или `плагин:модуль`).
- `/pn modules plugins`: плагины с модулями и числом библиотек.
- `/pn modules libs [<плагин>|<плагин:модуль>]`: библиотеки с названием, описанием, режимом загрузки и предупреждениями
  («сумма ещё не проверена», «другая версия у другого плагина»).
- Меню: главная, «Библиотеки плагинов» (сначала выбор плагина или «Все библиотеки»; у библиотеки видно, чья она, файл и папка от корня сервера) и «Модули плагинов»; карточка плагина обновлений, «Библиотеки»; карточка модуля,
  «Библиотеки». У модуля в списке виден его `description`.

## Диск: сколько места занимают плагины и библиотеки

`/pn modules disk` и кнопка «Диск плагинов» на главной странице меню (право `pnlibrary.modules`) показывают, сколько места
занимает каждый плагин сервера, не только наши. Для каждого плагина считается:

| Часть | Что в неё входит |
|---|---|
| плагин | jar плагина в папке `plugins` |
| настройки | `yml`, `yaml`, `json`, `toml`, `properties`, `conf`, `cfg`, `hocon`, `ini`, `xml` в его папке |
| библиотеки | файлы в папках `lib`, `libs`, `libraries` его папки |
| журналы | `*.log`, папка `logs`, сжатые журналы |
| данные | всё остальное: базы, кэши, сохранения |

Сверху итог: сколько занято всего, сколько весят библиотеки, зарегистрированные через pnLibrary, сколько свободно на диске и какой
он по размеру. Плагины идут от самого большого; тот, что занимает половину и больше, подсвечен.

Jar без папки (плагин без своих файлов) считается отдельным плагином. Jar и папка склеиваются по имени без версии: `Shop-1.2.3.jar`
и папка `Shop` дают одну строку.

В `/pn modules libs` и в карточке библиотеки в меню теперь видны размер jar и место, где он лежит. Пока библиотека не загружена
или нет загрузчика, этих полей нет.

Подсчёт папки запоминается на 30 секунд, чтобы клики по меню не обходили диск каждый раз. Если плагинов много и папки огромные,
первое открытие может занять секунду. Меню другого сервера показывает диск того сервера.
