# План системы обновлений pnLibrary

## Цель

Сделать обновления предсказуемыми: ручная проверка всегда получает свежий список GitHub-релизов, каждый компонент настраивается отдельно, а временная пауза не превращается в постоянное отключение критичных обновлений.

## Конфигурация

```yaml
updates:
  # Главный переключатель всей системы обновлений.
  enabled: true

  library:
    # Библиотека всегда проверяет обновления. Отключить саму проверку нельзя.
    # Этот флаг управляет только скачиванием и установкой найденного плана.
    automatic-download: false

  plugins:
    # Глобальное разрешение проверки обновлений сторонних плагинов.
    enabled: true

    # Разрешает автоматическую загрузку найденного обновления.
    # false — только сообщить; true — подготовить файл к перезапуску.
    automatic-download: false

    # Исключения задаются для конкретных плагинов, а не для всех сразу.
    plugins:
      acceptance:
        # enabled — проверять этот плагин.
        # disabled — не скачивать обновления этого плагина.
        mode: enabled

        # Временная пауза только для acceptance. Максимум 7 дней.
        # После даты проверка включается автоматически.
        pause-until: null

      another-plugin:
        mode: disabled
        pause-until: null
```

## Термины и режимы

В конфигурации и пользовательских сообщениях используется только слово `плагин`.

Один плагин обычно является одним объектом обновления. Внутри API допускается несколько компонентов, но эта внутренняя структура не отображается в пользовательской конфигурации.

Администратор может отключить обновление всего плагина. Если разработчику нужно управлять отдельным внутренним компонентом, это делается через API плагина, а не через YAML пользователя.

Интервал фоновой проверки не задаётся пользователем. Он фиксируется разработчиком при регистрации плагина в коде. Пользователь может только включить или запретить загрузку найденного обновления.

| Режим | Значение |
|---|---|
| `enabled` | Проверять компонент и сообщать о новой версии. |
| `disabled` | Проверять можно, но не скачивать обновление конкретного плагина. |
| `normal` | Обычная проверка без автоматической загрузки. |

У библиотеки нет режима отключения проверки. Она всегда получает список релизов, проверяет совместимость и строит план. `automatic-download: false` только запрещает скачивание и установку найденного плана. Это позволяет администратору остановить изменения, не отключая диагностику.

`pause-until` — это не постоянное отключение. Значение ограничено семью днями от момента записи. После истечения срока система сама возвращает компонент в рабочий режим.

## Алгоритм проверки

```text
GitHub API
→ свежий список релизов
→ канал
→ версия
→ платформа
→ Java
→ artifact-pattern
→ component.json внутри JAR
→ совместимый результат
```

## Совместное обновление библиотеки и плагинов

Обновление библиотеки рассматривается как граф зависимостей:

1. библиотека получает новый релиз и его диапазон API;
2. для каждого зарегистрированного плагина проверяется совместимость с новым API;
3. несовместимый плагин ищется в более новой версии;
4. если совместимая версия найдена, она добавляется в общий план обновления;
5. если обновления нет, библиотека не устанавливает несовместимый план и показывает, какой плагин блокирует обновление;
6. если все компоненты совместимы, библиотека готовит единый атомарный план и применяет его только при разрешённой загрузке.

Таким образом, библиотека может сообщить: «обновление есть, но его блокирует плагин X», а не сломать работающую связку компонентов.

## Ошибка после обновления

После перезапуска система проверяет, что каждый обновлённый плагин действительно загрузился.

- если плагин включился — обновление подтверждается;
- если плагин не включился — обновление получает состояние `FAILED` и помечается причиной;
- автоматического отката нет: администратор сам выбирает действие;
- доступны команды просмотра плана, повторной установки и ручного отката на сохранённый предыдущий JAR.

Пользователь видит, какой плагин не запустился, какую версию установили и какой файл можно восстановить.

Ручная команда `/pn update <component>` игнорирует устаревший кэш и делает свежий запрос. Фоновая проверка использует кэш только до истечения заданного интервала.

## Сообщения

Каждый результат должен быть понятен:

- обновление найдено: текущая и новая версия;
- компонент отключён настройкой;
- компонент временно приостановлен и дата окончания паузы;
- релиз найден, но подходящего JAR нет;
- JAR есть, но metadata несовместима;
- GitHub недоступен или вернул 404.

## Проверки перед выпуском

- текущая версия;
- найденное обновление;
- отдельное отключение одного плагина;
- пауза одного плагина на 1–7 дней;
- автоматическое окончание паузы;
- критическое обновление библиотеки;
- неправильный artifact-pattern;
- несовместимые Java/API/platform;
- пустой релиз и HTTP 404;
- очистка и повторное заполнение кэша.
