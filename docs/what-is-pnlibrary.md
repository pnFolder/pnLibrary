# pnLibrary простыми словами

`pnLibrary` — общая библиотека pnFolder для Bukkit/Paper, BungeeCord и Velocity-плагинов. Она предоставляет готовый runtime и единые правила, чтобы каждый плагин не реализовывал одни и те же сервисы заново.

## Что получает плагин

### Контекст и жизненный цикл

При включении плагин регистрируется в библиотеке и получает контекст. Через контекст доступны идентификатор плагина, версия, платформа, состояние запуска и зарегистрированные сервисы. Модуль можно включать и отключать независимо, а ошибки регистрации не должны незаметно продолжать запуск плагина.

### Регистрация продукта

Плагин объявляет один продукт и его метаданные:

```kotlin
plugin.registerModule("pnmarket") {
    it.product(
        ProductDescriptor.builder()
            .version(description.version)
            .pnLibraryApi(1, 1)
            .build()
    )
}
```

`version` — версия самого плагина. `pnLibraryApi` — диапазон API библиотеки, который плагин умеет использовать. Канал обновлений задаётся каталогом релизов, а не суффиксом версии.

### Обновления

Библиотека периодически и по команде проверяет каталог релизов. Проверка и скачивание — разные операции:

1. получить каталог;
2. выбрать релиз указанного продукта;
3. проверить канал, API, платформу, Java и артефакт;
4. показать результат администратору;
5. скачать только после явной команды, если автозагрузка отключена.

Поддерживаемые каналы: `stable`, `rc`, `beta`, `alpha`, `dev`. Канал берётся исключительно из поля `channel` в каталоге:

```json
{
  "version": "2.2.0-rc.1",
  "channel": "rc"
}
```

Суффикс `-rc.1` сам по себе канал не меняет. Поэтому автор релиза обязан правильно указать `channel`.

### Совместимость

Перед выбором обновления проверяются:

- диапазон API pnLibrary;
- тип платформы (Bukkit/Paper, BungeeCord или Velocity);
- версия Java;
- ограничения Minecraft для серверных платформ;
- наличие подходящего JAR в каталоге;
- доступность и корректность URL.

Если совместимый релиз не найден, библиотека ничего не скачивает и сообщает причину.

### Зависимости

Плагин может объявить зависимость от другого продукта. При обновлении библиотека учитывает цепочку зависимостей и не предлагает заведомо несовместимый набор версий. Откат автоматически не выполняется: решение об откате принимает администратор.

### Конфигурация

Конфигурация хранится в `plugins/pnLibrary/`. В ней задаются выбранный канал, расписание проверки, разрешение ручной/автоматической загрузки и временные паузы для отдельных плагинов. Интервал проверки является настройкой библиотеки, а не пользовательским параметром регистрации плагина.

### Диагностика

Библиотека предоставляет единый снимок состояния: ядро сервера, Java, платформу, установленную версию, выбранный канал, последние релизы и найденные совместимые обновления. Для диагностики используются команды `/pn` и `/pn update-status`; для ручной проверки конкретного продукта — `/pn update <plugin>`.

### Валюта и дополнительные сервисы

В состав библиотеки также входят общие сервисы для плагинов:

- контракты валют и хранилищ;
- операции баланса, переводы и история;
- права, подтверждения и команды валюты;
- конфигурации, namespaces и безопасные действия;
- задачи и platform-aware выполнение;
- диагностические логи и безопасный системный снимок;
- метрики.

Конкретный плагин подключает только нужные сервисы через свой контекст.

## Что pnLibrary не делает

- не заменяет Bukkit/Paper или прокси-ядро;
- не включает сторонний плагин вместо администратора;
- не скачивает обновления без разрешённой политики;
- не считает имя файла доказательством версии или канала;
- не выполняет автоматический откат после неудачного обновления;
- не требует от каждого плагина собственной реализации updater, диагностики и общих сервисов.

## Жизненный цикл обновления

```text
каталог релизов
      ↓
проверка channel + API + Java + platform
      ↓
совместимый кандидат
      ↓
уведомление администратора
      ↓
/pn update <plugin>
      ↓
загрузка и проверка JAR
      ↓
замена файла и перезапуск сервера
```

Главный принцип: каталог описывает релиз явно, а библиотека проверяет его совместимость и безопасно сообщает результат.
