# API Compatibility Guardrails Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish an independent integer API generation, checked public ABI baselines, and generated release metadata/checksums.

**Architecture:** Public version primitives live in `pnlibrary-api`. Kotlin's built-in ABI validation records the public JVM surface; a repository policy script compares a merge base ABI/generation with the current files so additions remain legal while removals require a generation increase. Gradle distribution tasks generate deterministic JSON metadata and SHA-256 sidecars from project properties.

**Tech Stack:** Kotlin 2.1.21, Gradle Kotlin DSL, JUnit Jupiter, PowerShell/Python-free Gradle tasks, GitHub Actions

**Spec:** `docs/superpowers/specs/2026-09-17-pnlibrary-architecture-and-pnupdate-design.md`

## Global Constraints

- `PnLibraryApi.VERSION` is an integer independent of `project.version`.
- The initial generation is `4`, matching the supplied pnUpdate/API specification examples.
- Compatible additions do not require a generation increase.
- Removed or changed ABI declarations require an increased generation.
- Public API metadata uses inclusive minimum and maximum generations.
- Generated JSON and checksum files are deterministic and UTF-8.
