# pnLibrary Observability Black Box Design

## Goal

Объединить диагностику, журнал активности, запись ошибок, вложения и зашифрованные отчёты в одну внутреннюю систему pnLibrary. Существующий `DiagnosticsService` сохраняется как совместимый фасад.

## Constraints

- Система работает локально и не отправляет данные автоматически.
- Retention, лимиты, маскирование и правила вложений задаются только в коде pnLibrary.
- Пользовательская конфигурация не управляет аналитикой, сроками хранения или составом отчёта.
- Старые вызовы `DiagnosticsService` продолжают работать.
- Персональные данные, токены, пароли и IP не попадают в обычные записи.
- Отчёт создаётся только по явной административной команде.
- Автоматическое удаление не затрагивает критические события и события, связанные с незавершённым отчётом.

## Unified model

Внутренний сервис называется `ObservabilityService` и объединяет пять слоёв:

1. `ActivityJournal` — события жизненного цикла, обновлений, команд и компонентов.
2. `ErrorRecorder` — ошибки с корневой причиной и stack trace.
3. `DiagnosticState` — актуальные статусы компонентов и снимки состояния.
4. `AttachmentStore` — файлы, привязанные к событию или отчёту.
5. `ReportService` — сборка, шифрование, локальное сохранение и ручная загрузка отчёта.

Старый `DiagnosticsService` делегирует записи в `ObservabilityService`, поэтому плагины не требуют немедленной миграции.

## Event model

Каждое событие содержит идентификатор, UTC-время, тип, категорию, уровень важности, источник, продукт, correlation ID и ограниченные строковые поля. Связанные действия используют один `correlationId`, например весь цикл проверки обновления.

Уровни: `TRACE`, `INFO`, `NOTICE`, `WARNING`, `ERROR`, `CRITICAL`.

Событие может иметь несколько вложений. Вложение получает безопасное имя, MIME-тип, размер, SHA-256 и внутренний идентификатор. Исходный путь не используется как путь хранения.

## Retention

Правила фиксируются в коде:

| Уровень | Срок |
|---|---:|
| TRACE | 6 часов |
| INFO | 7 дней |
| NOTICE | 30 дней |
| WARNING | 30 дней |
| ERROR | 90 дней |
| CRITICAL | бессрочно |

Очистка выполняется при запуске и периодически внутренним планировщиком. Критические события удаляются только явной административной операцией.

## Attachments

Вложения добавляются только через API библиотеки и связываются с `eventId` или `reportId`. Разрешаются текстовые, JSON, диагностические и архивные данные; исполняемые файлы запрещены. Перед сохранением применяются лимит размера, проверка MIME-типа, контроль SHA-256 и очистка секретов.

## Binary report

Отчёт является контейнером формата `PNR1`:

```text
manifest.json
environment.json
current-state.json
activity.jsonl
errors.jsonl
attachments/*
checksums.json
```

Сначала создаётся ZIP, затем он шифруется существующим `EncryptedEnvelopeCodec`. Расшифровка выполняется отдельной утилитой поддержки; сервер и пользователь не получают открытый архив автоматически.

## Compatibility

- `DiagnosticsService.record` преобразуется в событие `ObservabilityService`.
- `DiagnosticsService.status` обновляет `DiagnosticState`.
- Существующий `createDiagnosticReport` использует новый `ReportService`.
- Существующие отчёты и настройки шифрования остаются читаемыми.
- Новый API добавляется без удаления старых публичных методов.

## Failure handling

- Ошибка записи журнала не должна ломать основной плагин.
- Ошибка добавления вложения записывается как отдельное диагностическое событие.
- Повреждённая строка журнала пропускается и не блокирует загрузку остальных событий.
- Если отчёт не удалось загрузить, локальный зашифрованный файл сохраняется.
- При переполнении лимита сначала удаляются старые некритичные события, затем отклоняется новое вложение с понятной причиной.

## Success criteria

- Старые диагностики продолжают работать.
- Обычная ошибка видна в журнале вместе с контекстом.
- Серьёзная ошибка сохраняет stack trace и вложения.
- Отчёт содержит историю, состояние и файлы в одном бинарном контейнере.
- Пользователь не настраивает retention и внутренние лимиты.
- Критические инциденты не исчезают автоматически.
