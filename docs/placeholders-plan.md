# Плейсхолдеры: план системы

Статус: решения согласованы с пользователем, реализация идёт по шагам. Ветка `next`.
Что уже сделано в коде: адрес `плагин/модуль:имя` и поиск по нему (`PlaceholderAddress`, `PlaceholderAddressIndex`).

## 1. Адрес

- Полный адрес всегда из трёх частей: `плагин/модуль:имя`, например `pnclans/war:score`.
- Плагин без модулей получает модуль `main`: `pnclans/main:score`.
- Внутри своего плагина можно писать короткое имя `{score}`: библиотека сама достроит `pnclans/<модуль>:score`.
  Чужие плейсхолдеры всегда полным адресом.
- В идентификаторах плагина и модуля запрещены `/`, `:` и (для плагина) `_`. Имя может содержать `.` и `{}`
  (шаблоны вида `player.{name}.kills`).

## 2. Как пишется в тексте

- Наши плейсхолдеры в фигурных скобках: `{pnclans/war:score}`. Это конфиги, сообщения, меню.
- Формат через `|`: `{pnclans/war:score|number|upper}`.
- Условные блоки внутри шаблона остаются как сейчас.
- Чужие плейсхолдеры PlaceholderAPI в процентах: `%vault_eco_balance%`.

## 3. Один прогон текста

`render(text, player)` делает по порядку:
1. Наши `{…}` через реестр библиотеки.
2. Оставшиеся `%…%` отдаются в PlaceholderAPI, если он установлен. Нет его, остаются как есть.
3. Всё не найденное остаётся в тексте без изменений.

Плагины вызывают только этот метод и не думают, чьи плейсхолдеры в тексте.

## 4. Доступ

- По умолчанию читать плейсхолдер может любой плагин. Владелец может ограничить: только он сам или список плагинов.
- Запись значения извне (`update`) по умолчанию закрыта, владелец разрешает её отдельно.

## 5. Что умеет плейсхолдер

- Форматы через `|`.
- Параметры в имени (`player.{name}.kills`), параметры доходят до обработчика.
- Запись значения извне (по правилу владельца).
- Условные блоки и кэш значений (время кэша задаёт владелец).

## 6. Потоки

- Вычисление асинхронное, результат через `CompletionStage`.
- Для PlaceholderAPI (он ждёт ответ сразу, часто на главном потоке):
  1. Если есть свежий кэш, отдаём его.
  2. Если есть старое значение, отдаём его и обновляем в фоне.
  3. Если значения ещё нет, на потоках вне главного ждём не дольше короткого лимита (до 1 секунды),
     на главном потоке не дольше одного тика (50 мс). Не успели, отдаём запасной текст (по умолчанию пусто)
     и значение прогреется в фоне.
- Лимит на главном потоке намеренно короче: ожидание в секунду на главном потоке вешает весь сервер.

## 7. Публикация в PlaceholderAPI

- Публикует автор плагина, в коде, явно, и сам задаёт префикс. Без указанного префикса ничего не публикуется.
- Префикс: `a-z0-9-`, не короче 2 символов, без `_` (PlaceholderAPI делит по первому `_`).
- Вид снаружи: `%префикс_модуль~имя%`. Если автор публикует плейсхолдеры одного модуля, можно без модуля:
  `%префикс_имя%`.
- У плагина может быть несколько префиксов; каждому сопоставляется набор публикуемых плейсхолдеров.
- Занятый префикс (уже есть у другого плагина) находится при старте: второй не регистрируется, ошибка идёт в журнал,
  сервер не падает.
- Родной адрес `pnclans/war:score` внутри библиотеки не меняется. PlaceholderAPI формат `%pnclans/war:score%`
  не пропускает (нет `_`), проверено по его исходникам.

## 8. Встроенные плейсхолдеры библиотеки

Под адресом `pnlibrary/main:…`: версия, платформа, число плагинов, время работы и данные из `/pn stats`.
Доступны всем плагинам.

## 9. Для администратора

- `/pn placeholders`: список с адресом, владельцем, доступом, публикацией в PlaceholderAPI и префиксом.
- `/pn placeholders test <адрес> [игрок]`: вычислить вручную и показать значение или ошибку.
- Страница в меню `/pn gui` с теми же данными.
- Ошибки пишутся в `/pn events`: неизвестный адрес, упавший resolver, конфликт префикса.
- Право: `pnlibrary.placeholders` (объявить в `plugin.yml`, README и списках прав вместе с командой).

## 10. Ошибки

Не найден или упал: в тексте остаётся `{адрес}`, причина пишется в журнал. Игрок видит, что не подставилось,
админ видит почему.

## 11. Порядок работ

1. Сделано: адрес и поиск по адресу.
2. Короткие имена внутри своего плагина.
3. Общий прогон `render` с PlaceholderAPI и его адаптер для Bukkit.
4. Публикация с явным префиксом, проверка занятых префиксов.
5. Политика ожидания и кэша для ответов PlaceholderAPI.
6. Встроенные `pnlibrary/main:…`.
7. `/pn placeholders`, `test`, страница меню, право.
8. Перевод старых ключей и адаптеры для совместимости (плагины на dev.6 запускаются без пересборки).
