# Плейсхолдеры: план системы

Статус: решения согласованы с пользователем, реализация идёт по шагам. Ветка `next`.
Что уже сделано в коде: адрес `плагин/модуль:имя` и поиск по нему (`PlaceholderAddress`, `PlaceholderAddressIndex`).

## 1. Адрес

- Полный адрес всегда из трёх частей: `плагин/модуль:имя`, например `pnclans/war:score`.
- Плагин без модулей получает модуль `main`: `pnclans/main:score`.
- Внутри своего плагина можно писать короткое имя `{score}`: библиотека сама достроит `pnclans/<модуль>:score`.
  Чужие плейсхолдеры всегда полным адресом.
- В идентификаторах плагина и модуля запрещены `/`, `:` и (для плагина) `_`. Имя может содержать `.` и `{}`
  (шаблоны вида `player.{name}.kills`).

## 2. Как пишется в тексте

- Наши плейсхолдеры в фигурных скобках: `{pnclans/war:score}`. Это конфиги, сообщения, меню.
- Формат через `|`: `{pnclans/war:score|number|upper}`.
- Условные блоки внутри шаблона остаются как сейчас.
- Чужие плейсхолдеры PlaceholderAPI в процентах: `%vault_eco_balance%`.

## 3. Один прогон текста

`render(text, player)` делает по порядку:
1. Наши `{…}` через реестр библиотеки.
2. Оставшиеся `%…%` отдаются в PlaceholderAPI, если он установлен. Нет его, остаются как есть.
3. Всё не найденное остаётся в тексте без изменений.

Плагины вызывают только этот метод и не думают, чьи плейсхолдеры в тексте.

## 4. Доступ

Всё, что зарегистрировано, видно другим плагинам библиотеки. Публикация наружу, в PlaceholderAPI, отдельный шаг (п. 7).

- По умолчанию читать плейсхолдер может любой плагин.
- Автор может изменить правило на плейсхолдере или сразу на модуле (правило модуля общее, плейсхолдер может его
  переопределить):

```kotlin
module("war") {
    access { denyAll() }                       // закрыть весь модуль
    placeholder<Int>("score") { ... }
    placeholder<Int>("kills") { ... }.access { allowOnly("pnshop", "pnbank") }
    placeholder<Int>("rank")  { ... }.access { deny("pnspy") }       // всем, кроме перечисленных
}
```

- Правила: `allowAll()` (по умолчанию), `denyAll()`, `allowOnly(...)`, `deny(...)`. Игрок и консоль не плагины,
  правило касается только плагинов библиотеки.
- Запрет всегда сильнее разрешения: плагин из `deny` не прочитает, даже если модуль открыт.
- Отказ в доступе не роняет текст: значение не подставляется, причина идёт в журнал (`/pn events`).
- Запись значения извне (`update`) по умолчанию закрыта, владелец разрешает её отдельно.

## 4a. Регистрация и запрос

Плейсхолдеры строятся деревом, как команды (`literal`, `argument`): ветка может иметь своё значение и продолжаться
дальше. Всё регистрируется в одном месте, внутри модуля. Публикация в PlaceholderAPI задаётся там же.

```kotlin
module("war") {
    placeholders(papi = "clans") {
        int("score") {                                   // {pnclans/war:score}
            value { clans.scoreOf(player) }              // значение самой ветки
            int("kills") { value { clans.killsOf(player) } }        // {pnclans/war:score.kills}
            text("top") {                                // {pnclans/war:score.top}
                value { clans.topName(1) }
                param("place") { clans.topName(arg.int()) }         // {pnclans/war:score.top.3}
            }
        }
        number("bank") { value { clans.bank(clanOf(player)) } }
        int("debug") { value { 1 }; inside() }           // только для {…}, наружу не публиковать
    }
}
```

- Имя плейсхолдера складывается из пути: `score` -> `score.kills` -> `score.top.3`. Параметр (`param`) занимает
  место одной части пути, как `argument` в команде.
- Ветка может не иметь своего значения (`value` не нужен): тогда она только группирует.
- Типы коротко: `int`, `number`, `text`, `bool`; любой другой `value<Тип>("имя") { … }`.
- `placeholders(papi = "префикс")` публикует все плейсхолдеры группы (включая ветки) под этим префиксом.
  Без `papi` наружу ничего не публикуется. `inside()` исключает ветку вместе с потомками.
- В PlaceholderAPI путь остаётся тем же, `.` внутри имени: `%clans_war~score.top.3%`.
- Группы в модуле можно повторять, у каждой свой префикс.
- Тело `value { }` работает с запросом как с получателем: `player` (может быть пустым), `arg` (значение
  параметра ветки: `arg.int()`, `arg.text()`), `caller` (плагин, который спрашивает), `values["ключ"]`.
- Доступ (п. 4): `access { allowOnly("pnshop") }` на группе, ветке или модуле; ветка наследует правило родителя,
  если не задала своё.
- Внутри реестр по-прежнему хранит плоские имена (`score.top.{place}`), дерево только способ записи,
  поэтому существующий поиск по адресу и шаблоны работают без изменений.

## 4b. Аргументы (игроки, числа, выбор)

Параметр ветки имеет тип. Тип проверяет и превращает кусок текста в значение, и сам подсказывает админу, что
ожидается. Неверное значение не падает: плейсхолдер остаётся в тексте, причина в журнале.

```kotlin
module("war") {
    placeholders(papi = "clans") {
        int("score") {
            value { clans.scoreOf(player) }                                // {pnclans/war:score}       -> очки того, для кого рендерим
            player("who") { value { clans.scoreOf(arg) } }                 // {pnclans/war:score.Alex}  -> очки игрока Alex (ник или UUID)
            int("top") {
                param("place", range = 1..100) { value { clans.topScore(arg) } }   // {pnclans/war:score.top.3}
            }
        }
        text("clan") {
            value { clans.clanOf(player)?.name }                           // {pnclans/war:clan}
            choice("field", "name", "tag", "members") { value { clans.clanField(player, arg) } }   // {pnclans/war:clan.tag}
        }
    }
}
```

- Типы аргумента: `player` (ник или UUID, находит игрока в сети или в хранилище, доступно как `arg`), `int`,
  `number`, `text`, `bool`, `choice(варианты)`. Для `int`/`number` можно указать `range`.
- `player(...)` отдаёт объект игрока, а не строку. Если игрока нет, плейсхолдер считается ненайденным, без падения.
- Подсказки: `/pn placeholders` показывает для ветки её параметры и допустимые значения.

## 4c. Форматирование

Формат применяется после значения через `|`, цепочкой слева направо:

```
{pnclans/war:score|number}              -> 1 234 567
{pnclans/war:score.Alex|number|pad(8)}  -> "   1 234"
{pnclans/war:clan.name|upper}           -> RED WOLVES
{pnclans/war:bank|money}                -> 12 500 монет
{pnclans/war:uptime|duration}           -> 2д 3ч
```

- Встроенные форматы: `number`, `round(n)`, `percent`, `money`, `duration`, `date`, `upper`, `lower`, `title`,
  `pad(n)`, `trim`, `default(текст)` (запасное значение, если пусто).
- Тип значения определяет, какие форматы применимы: число принимает `number`, `round`, текст принимает `upper`.
  Неподходящий формат не падает: значение остаётся как есть, предупреждение в журнал.
- Свой формат автор регистрирует рядом с плейсхолдерами, и он виден всем плагинам библиотеки:

```kotlin
module("war") {
    formats {
        format<Int>("rank") { value -> "#$value" }                          // {pnclans/war:score|war/rank}
    }
}
```

- Формат по умолчанию для самого плейсхолдера: `int("bank") { format("money"); value { … } }`. Тогда
  `{pnclans/war:bank}` сразу даёт `12 500 монет`, а `{pnclans/war:bank|number}` перезапишет его.
- Формат тоже имеет адрес, как плейсхолдер: `плагин/модуль` + имя; без адреса берутся встроенные.

## 4d. Все вариации дерева

Любая ветка (обычная или с аргументом) может иметь своё значение и продолжаться дальше без ограничения глубины.
Аргумент в пути можно ставить где угодно, в том числе несколько подряд и после других аргументов.

```kotlin
module("war") {
    placeholders(papi = "clans") {
        int("score") {                                              // {pnclans/war:score}                        очки того, для кого рендерим
            value { clans.scoreOf(player) }
            player("who") {                                         // {pnclans/war:score.Alex}                   очки Alex
                value { clans.scoreOf(arg) }
                int("kills") { value { clans.killsOf(arg) } }       // {pnclans/war:score.Alex.kills}             убийства Alex
                text("clan") {                                      // {pnclans/war:score.Alex.clan}              клан Alex
                    value { clans.clanOf(arg)?.name }
                    choice("field", "tag", "members") {             // {pnclans/war:score.Alex.clan.tag}          поле клана Alex
                        value { clans.clanField(clans.clanOf(arg), argOf("field")) }
                    }
                }
                param("season", int) {                              // {pnclans/war:score.Alex.3}                 очки Alex в сезоне 3
                    value { clans.scoreOf(argOf("who"), season = arg) }
                    int("kills") { ... }                            // {pnclans/war:score.Alex.3.kills}           убийства Alex в сезоне 3
                }
            }
            int("top") {                                            // {pnclans/war:score.top}                    лидер
                value { clans.topScore(1) }
                param("place", int, range = 1..100) {               // {pnclans/war:score.top.3}                  третье место
                    value { clans.topScore(arg) }
                    player("name") { ... }                          // {pnclans/war:score.top.3.name}             ник третьего
                }
            }
        }
    }
}
```

Правила:
- Путь читается слева направо, каждая часть это либо имя ветки, либо значение аргумента. Первое, что подошло по
  типу, выигрывает; имя ветки сильнее аргумента (`top` не станет ником игрока, если есть ветка `top`).
- Значение любого уровня: `arg` (последний аргумент) и `argOf("имя")` (любой аргумент по пути). Родительские
  аргументы доступны потомкам.
- Один уровень может иметь и имена, и аргумент одновременно (`score.top` и `score.Alex`). Если ник совпал с
  именем ветки, выигрывает ветка; точный игрок указывается через `player:Alex`.
- Ветка без `value` только группирует: `{pnclans/war:score.top}` без значения ответит «не найдено».
- Глубина не ограничена, но в `/pn placeholders` дерево показывается раскрывающимся списком, а длинные пути
  видны полностью (`score.Alex.clan.tag`).

## 4e. Свои форматы: все варианты

Свой формат это функция «значение в текст». Регистрируется один раз и доступен как `{…|имя}`, цепочкой с другими.

```kotlin
module("war") {
    formats {
        format<Int>("rank") { "#$it" }                               // {pnclans/war:score|war/rank}           -> #3
        format<Int>("stars", count = true) { n -> "★".repeat(n) }    // {pnclans/war:score|war/stars}          -> ★★★
        format<Int>("pad0", arg = int) { n, width -> "%0${width}d".format(n) }   // {pnclans/war:score|war/pad0(5)}   -> 00042
        format<String>("tag") { "[$it]" }                            // {pnclans/war:clan.tag|war/tag}         -> [WOLF]
        format<Any>("safe") { it?.toString() ?: "—" }                // для любого типа
    }
}
```

- Форматы принимают тип значения (`Int`, `String`, `Any`) и необязательные аргументы в скобках (`pad0(5)`).
- Формат автора лежит в его модуле: полный вызов `{…|плагин/модуль:имя}` или короткий `war/rank` внутри
  своего плагина. Встроенные вызываются без адреса.
- Формат может быть общим для плагина (вне модуля) и виден всем плагинам, как и плейсхолдеры (доступ тот же).
- Цепочка: `{pnclans/war:score.Alex|number|war/rank|pad(8)}`: каждый следующий получает результат предыдущего
  (после первого преобразования значение становится текстом).
- Ошибка внутри формата не роняет текст: значение подставляется без этого формата, в журнал идёт запись.
- Формат по умолчанию для плейсхолдера или всей группы: `format("money")`; перекрывается любым `|` в тексте.

## 4f. Формат: нужен не везде, и гибко

Формат всегда необязателен. У значения четыре уровня, каждый следующий сильнее:

1. Без формата: значение как есть (по умолчанию).
2. Формат группы: `placeholders { format("number") }` действует на всё в группе.
3. Формат плейсхолдера: `int("bank") { format("money") }` перекрывает группу; `format(none)` отключает формат группы.
4. Формат в тексте: `{…|round(2)}` перекрывает всё выше. `{…|raw}` отключает любой формат по умолчанию.

```kotlin
placeholders(papi = "clans") {
    format("number")                       // группа: числа с разделителем
    int("score")  { value { … } }          // 1 234               (формат группы)
    int("id")     { format(none); value { … } }                 // 1234     (без формата)
    number("bank"){ format("money"); value { … } }              // 12 500 монет
}
// {pnclans/war:score}        -> 1 234
// {pnclans/war:score|raw}    -> 1234
// {pnclans/war:bank|round(0)}-> 12500
```

Админ может менять настройки встроенных форматов (разделитель тысяч, локаль, подпись валюты, число знаков),
не трогая плагины. Настройки хранятся аннотациями конфига библиотеки, а не отдельным текстовым файлом.

## 4g. Генерация плейсхолдеров из данных

Чтобы не писать каждую ветку руками, дерево строится из данных автоматически:

```kotlin
placeholders(papi = "clans") {
    // Из класса: каждое свойство становится веткой, тип определяется сам
    from<Clan>("clan") { clans.clanOf(player) }
    //   {pnclans/war:clan.name}  {pnclans/war:clan.tag}  {pnclans/war:clan.members}  {pnclans/war:clan.bank}
    //   (data class Clan(val name: String, val tag: String, val members: Int, val bank: Double))

    // Из класса с игроком в начале пути: clan.<игрок>.name
    from<Clan>("clan", by = player("who")) { clans.clanOf(arg) }
    //   {pnclans/war:clan.Alex.name}

    // Из таблицы значений
    table("price", keys = { shop.items() }) { item -> shop.priceOf(item) }
    //   {pnclans/war:price.sword}  {pnclans/war:price.apple}

    // Из списка с номером места
    list("top", size = { 100 }) { place -> clans.topName(place) }
    //   {pnclans/war:top.1}  {pnclans/war:top.2} … {pnclans/war:top.100}
}
```

- Какие свойства попадают в дерево, управляется аннотациями или параметрами: `exclude(Clan::secret)`,
  `only(Clan::name, Clan::tag)`, `rename(Clan::members, "size")`.
- Вложенные классы раскрываются глубже (`clan.leader.name`), пока это не цикл; глубину можно ограничить.
- Форматы и доступ задаются как у обычных веток; на `from` и `table` они действуют на все порождённые ветки.
- `/pn placeholders` показывает порождённые ветки так же, как ручные.

## 4h. Как это видно в PlaceholderAPI

| Наш адрес | В PlaceholderAPI |
|---|---|
| `pnclans/war:score` | `%clans_war~score%` |
| `pnclans/war:score.Alex.kills` | `%clans_war~score.Alex.kills%` |
| `pnclans/war:top.3` | `%clans_war~top.3%` |
| `pnclans/war:bank\|money` | формат в PlaceholderAPI не пишется: `%clans_war~bank%` |

- Знак `~` PlaceholderAPI не мешает: парсер учитывает только первый `_` и пробел до него (проверено по
  исходникам). Как `~` ведут себя чужие плагины, которые читают `%…%` сами (скорборды, табы), на живом сервере
  не проверялось. Если у кого-то `~` ломается, разделитель можно будет заменить на другой знак одной настройкой.
- Формат по умолчанию применяется и к значению, отданному в PlaceholderAPI. Чтобы отдать сырое, на ветке
  ставится `format(none)`.
- Число с дробной частью отдаётся без экспоненты (`0.5`, не `5E-1`); число знаков задаёт `round(n)` или формат
  ветки. Целые остаются целыми.
- PlaceholderAPI вызывает значение сразу, поэтому тяжёлое отдаётся из кэша (п. 6).

## 5. Что умеет плейсхолдер

- Форматы через `|`.
- Параметры в имени (`player.{name}.kills`), параметры доходят до обработчика.
- Запись значения извне (по правилу владельца).
- Условные блоки и кэш значений (время кэша задаёт владелец).

## 6. Потоки

- Вычисление асинхронное, результат через `CompletionStage`.
- Для PlaceholderAPI (он ждёт ответ сразу, часто на главном потоке):
  1. Если есть свежий кэш, отдаём его.
  2. Если есть старое значение, отдаём его и обновляем в фоне.
  3. Если значения ещё нет, на потоках вне главного ждём не дольше короткого лимита (до 1 секунды),
     на главном потоке не дольше одного тика (50 мс). Не успели, отдаём запасной текст (по умолчанию пусто)
     и значение прогреется в фоне.
- Лимит на главном потоке намеренно короче: ожидание в секунду на главном потоке вешает весь сервер.

## 7. Публикация в PlaceholderAPI

- Публикует автор плагина, в коде, явно, и сам задаёт префикс: прямо в группе `placeholders(papi = "префикс")`,
  отдельной регистрации нет. Без указанного префикса ничего не публикуется.
- Префикс: `a-z0-9-`, не короче 2 символов, без `_` (PlaceholderAPI делит по первому `_`).
- Вид снаружи: `%префикс_модуль~имя%`. Если автор публикует плейсхолдеры одного модуля, можно без модуля:
  `%префикс_имя%`.
- У плагина может быть несколько префиксов; каждому сопоставляется набор публикуемых плейсхолдеров.
- Занятый префикс (уже есть у другого плагина) находится при старте: второй не регистрируется, ошибка идёт в журнал,
  сервер не падает.
- Родной адрес `pnclans/war:score` внутри библиотеки не меняется. PlaceholderAPI формат `%pnclans/war:score%`
  не пропускает (нет `_`), проверено по его исходникам.

## 8. Встроенные плейсхолдеры библиотеки

Под адресом `pnlibrary/main:…`: версия, платформа, число плагинов, время работы и данные из `/pn stats`.
Доступны всем плагинам.

## 9. Для администратора

- `/pn placeholders`: список с адресом, владельцем, доступом, публикацией в PlaceholderAPI и префиксом.
- `/pn placeholders test <адрес> [игрок]`: вычислить вручную и показать значение или ошибку.
- Страница в меню `/pn gui` с теми же данными.
- Ошибки пишутся в `/pn events`: неизвестный адрес, упавший resolver, конфликт префикса.
- Право: `pnlibrary.placeholders` (объявить в `plugin.yml`, README и списках прав вместе с командой).

## 10. Ошибки

Не найден или упал: в тексте остаётся `{адрес}`, причина пишется в журнал. Игрок видит, что не подставилось,
админ видит почему.

## 11. Порядок работ

1. Сделано: адрес и поиск по адресу.
2. Короткие имена внутри своего плагина.
3. Общий прогон `render` с PlaceholderAPI и его адаптер для Bukkit.
4. Публикация с явным префиксом, проверка занятых префиксов.
5. Политика ожидания и кэша для ответов PlaceholderAPI.
6. Встроенные `pnlibrary/main:…`.
7. `/pn placeholders`, `test`, страница меню, право.
8. Перевод старых ключей и адаптеры для совместимости (плагины на dev.6 запускаются без пересборки).

## 12. Что сделано и чем отличается от плана
- Сделано: дерево, аргументы, форматы по уровням, генерация, доступ, публикация в PlaceholderAPI, `render`, `/pn placeholders`, встроенные форматы number, round, percent, money, group, short, duration, date, upper, lower, title, capitalize, pad, trim, default, plural, boolean.
- Аргументы формата пишутся как `имя:арг1,арг2`, например `pad:5,0`.
- Ожидание PlaceholderAPI на главном потоке 50 мс, вне его до 1 с.
- Не сделано: настройки форматов в аннотациях конфига, страница в `/pn gui`, адреса форматов `war/rank`, раскрытие вложенных классов в `from`.
- `PlaceholderInstaller` и `PlaceholderGeneration` остаются в `api` как `internal`: плагин их не видит. Модель дерева (`Node`, `Segment`) тоже `internal`; вынос в `core` потребовал бы сделать её публичной, а это хуже.
