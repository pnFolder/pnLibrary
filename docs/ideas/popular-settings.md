# Какие настройки выбирают другие

Статус: идея, не начата.

## Суть

У настроек, которые одинаково устроены у всех (включено/выключено, выбор из списка, число), библиотека может
показывать, какое значение чаще всего стоит у других серверов, например «это включено у 70% серверов» или
«значение `ru` выбрали 50%». Тогда администратор в меню или в чате видит, что выбирает большинство, и может
сравнить со своим выбором. Подсказка ничего не меняет сама.

## Как это может работать

1. **Что собираем.** Только значения настроек библиотеки из реестра (`core/settings`): ключ и выбранное значение.
   Никаких адресов, имён, путей, игроков и списков плагинов.
2. **Как отправляем.** Через уже существующую систему метрик (bStats, см. [metrics.md](../metrics.md)): каждая
   настройка с небольшим набором значений становится одной диаграммой «ключ → значение». Свои серверы для этого не нужны.
3. **Как получаем обратно.** Только если у платформы метрик есть публичный способ прочитать общую картину по
   диаграмме. Если такого способа нет, идею не делаем в этом виде: поднимать свой сервер ради подсказки не стоит.
4. **Что показываем.** В подсказке у пункта меню отдельная строка вроде `[ У других ] 70% — включено`, а в
   `/pn settings get` та же информация одной строкой. Данные кэшируются на диске в `data/` и обновляются редко.

## Что надо решить до начала

- **Можно ли получить данные из API метрик.** Это главное. Нужно проверить, отдаёт ли выбранный провайдер
  распределение значений по диаграмме без авторизации и без лимитов, и как часто.
- **Согласие.** Отправка включается только явно, и по умолчанию выключена. Сейчас метрики опциональны, так и оставляем.
  Получение чужой статистики не должно требовать отправки своей, либо это надо решить отдельно.
- **Какие настройки годятся.** Только те, где значений мало и они одинаковы у всех: переключатели, выбор из списка.
  Часовой пояс, числа, тексты и всё, что идентифицирует сервер, не отправляем.
- **Что считать «большинством».** Показывать процент только когда данных достаточно (например, от нескольких
  десятков серверов), иначе цифра вводит в заблуждение.
- **Прокси.** На прокси-сети настройки у каждого узла свои. Решить, считается ли сеть одним сервером.

## Куда это ложится в коде

- Реестр настроек (`SettingsRegistry`, `SettingSpec`) уже знает тип и допустимые значения каждой настройки.
  Нужен флаг «участвует в статистике» в `SettingSpec`, по умолчанию выключенный.
- Отправка: рядом с остальными диаграммами в `MetricsService`.
- Показ: строка в `LibrarySettingsScreens` и в `/pn settings get`, берёт данные из локального кэша.
- Хранение кэша: `data/` рядом с остальным состоянием библиотеки, см. [storage.md](../storage.md).
- Документация: когда идея будет сделана, описание уйдёт в [settings.md](../settings.md) и [metrics.md](../metrics.md).
