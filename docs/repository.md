# Папка `.pnlibrary` в репозитории плагина

Каждый плагин, который обновляется через pnLibrary, держит в корне своего репозитория папку `.pnlibrary`. Это единственный
источник правды о том, какие версии выпущены: pnLibrary читает список релизов оттуда, а не угадывает по GitHub.

```
.pnlibrary/
├── releases.json        список релизов (его читают обновления и установщик)
├── releases.example.json  образец заполненного списка
└── changelogs/
    ├── 1.0.0.md         описание версии 1.0.0
    └── 1.1.0.md         описание версии 1.1.0
```

Репозиторий читается с ветки `main`. Файлы нужно закоммитить в неё до выхода релиза.

## `releases.json`

```json
{
  "schema": 1,
  "product": "pnlibrary",
  "releases": [
    {
      "version": "1.1.0",
      "channel": "stable",
      "description": "Одна строка: что нового.",
      "changelogUrl": "https://github.com/pnFolder/pnLibrary/blob/main/.pnlibrary/changelogs/1.1.0.md",
      "publishedAt": "2026-10-16T12:00:00Z",
      "api": { "minimum": 8, "maximum": 8 },
      "installer": {
        "file": "pnLibrary-1.1.0-universal.jar",
        "url": "https://github.com/pnFolder/pnLibrary/releases/download/v1.1.0/pnLibrary-1.1.0-universal.jar",
        "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
        "size": 12345678
      },
      "artifacts": [
        {
          "file": "pnLibrary-1.1.0-velocity-java17.jar",
          "platform": "VELOCITY",
          "platformApi": { "minimum": "3.3", "maximum": "3.4" },
          "java": { "minimum": 17 },
          "url": "https://github.com/pnFolder/pnLibrary/releases/download/v1.1.0/pnLibrary-1.1.0-velocity-java17.jar"
        }
      ]
    }
  ]
}
```

| Поле | Смысл |
|---|---|
| `schema` | всегда `1` |
| `product` | id продукта, как он зарегистрирован в pnLibrary |
| `version` | версия релиза по semver; на GitHub ему соответствует тег `v<версия>` |
| `channel` | `stable`, `beta`, `alpha` или `dev`; обычные серверы получают только `stable` |
| `description` | короткое описание в одну строку, оно показывается в уведомлении |
| `changelogUrl` | ссылка на файл из `changelogs/` (необязательно) |
| `publishedAt` | время публикации в UTC |
| `api` | какие версии API pnLibrary поддерживает релиз |
| `installer` | универсальный JAR для первой установки встроенным установщиком (необязательно, см. ниже) |
| `artifacts` | файлы релиза по платформам: имя, платформа, диапазон версий платформы, Java и ссылка |

### Блок `installer`

Встроенный установщик (`PnLibraryBootstrap`) ставит один универсальный JAR `<имя>-<версия>-universal.jar`, который
подходит всем платформам. Если описать его в этом блоке, установщик берёт ссылку, размер и контрольную сумму прямо из
списка репозитория, а GitHub не спрашивает.

| Поле | Смысл |
|---|---|
| `file` | имя универсального JAR, обязательно вида `<имя>-<версия>-universal.jar` |
| `url` | ссылка на файл, только HTTPS |
| `sha256` | SHA-256 файла, 64 шестнадцатеричных символа; скачанный файл с другой суммой отклоняется |
| `size` | размер в байтах (необязательно); если указан, должен совпасть со скачанным |

Блок с ошибкой (чужое имя файла, не HTTPS, сумма не из 64 символов, слишком большой размер) пропускается, и файл с суммой
установщик берёт из GitHub-релиза этой версии. Обычные обновления блок `installer` не читают.

Правила: версии не повторяются, у релиза есть хотя бы один файл, ссылки только по HTTPS. Нарушение любого правила
сообщается с путём к полю (`releases[2].artifacts[0].url`). Пустой список `"releases": []` допустим.

## `changelogs/<версия>.md`

Пишете как хотите, в свободной форме. Правило одно: файл называется по версии. Для каждой версии из `releases.json`
должен быть файл, и тест репозитория проверяет это.

## Откуда берётся версия

1. **Обновления плагинов и самой pnLibrary** читают `releases.json` и сами выбирают подходящий файл (платформа, Java, API).
2. **Встроенный установщик** (`PnLibraryBootstrap.ensureInstalled`) выбирает версию так. Если плагин указал минимальную версию
   (`BootstrapOptions.builder("1.2.0")`), каждый шаг считает только версии не ниже неё; если не указал
   (`ensureInstalled(plugin)` или `BootstrapOptions.builder()`), подойдёт любая:
   1. **список репозитория** (`releases.json`): самый новый `stable`, а если стабильных там нет, самый новый из того,
      что есть (beta, alpha, dev, release candidate);
   2. **релизы GitHub**, если список пуст, не открылся или GitHub не отдаёт его версию: самый новый стабильный, а если
      стабильных нет, самый новый из любых (черновики не берутся);
   3. **ничего нет**: в консоли карточка «pnLibrary недоступна» с причиной и ссылкой на поддержку, плагин не запускается.

   Сам файл и его контрольную сумму установщик берёт из блока `installer` списка; если блока нет, из GitHub-релиза
   выбранной версии. Без контрольной суммы релиз не принимается. Если поставлена нестабильная версия, консоль прямо говорит об этом и подсказывает обновиться,
   когда выйдет стабильная.

Выпуск идёт так: добавить запись в `releases.json` и файл в `changelogs/`, закоммитить в `main`, затем опубликовать
релиз с тегом `v<версия>`.

## Откуда это значение: `gradle.properties`

Репозиторий, имя и id продукта, которые знает установщик, берутся из `pnlibrary.repository`, `pnlibrary.name` и
`pnlibrary.product-id` в `gradle.properties`. Менять их нужно только там.
