# Настройки библиотеки

У pnLibrary нет файлов настроек. Всё, что администратор может менять, меняется командой `/pn settings` или в меню
(`/pn gui` → «Настройки» → «Параметры библиотеки»). Значения хранятся в одном файле `plugins/pnLibrary/data/settings.json`:
в нём только то, что вы изменили, остальное берётся из кода. Файл не нужно править руками, но он безопасен: неизвестный ключ,
значение не того типа или вне границ пропускаются с предупреждением в консоли, берётся значение по умолчанию, сервер всё равно
запускается. Если файл вообще не читается, он сохраняется как `settings.json.broken`.

Рядом лежат три файла, которые библиотека создаёт сама и открывает для администратора: `Помощь.txt` (где получить помощь, ссылки на Discord и
репозиторий, главные команды), `Настройки.txt` (каждая настройка: ключ, название, текущее значение, по умолчанию, границы, когда заработает,
описание, готовая команда для изменения) и `Команды.txt` (каждая команда `/pn` и каждое право: что делает, какое право нужно, где команда есть).
Все пишутся заново при каждом запуске, `Настройки.txt` ещё и сразу после изменения настройки, поэтому значения и ссылки в них всегда
свежие, а ручные правки не сохраняются. Если JVM сервера не умеет создавать файлы с русскими именами (кодировка имён файлов не UTF-8), файлы
называются `HELP.txt`, `SETTINGS.txt` и `COMMANDS.txt`. Если записать их не удалось, в консоль выводится одно предупреждение, работа не страдает.

Единственный список настроек находится в коде (`SettingsRegistry`): команда, меню и тест документации читают его.
Тест проверяет, что каждая настройка описана на этой странице.

## Команда `/pn settings`

Право `pnlibrary.settings` (в меню подходит и `pnlibrary.admin`), консоль проходит всегда. Работает на играх-серверах и на прокси, на
прокси меняются настройки самого прокси.

| Команда | Что делает |
| --- | --- |
| `/pn settings [list] [страница]` | все настройки со значениями; изменённые отмечены значением по умолчанию (`включено`/`выключено` у переключателей) |
| `/pn settings get <ключ>` | одна настройка: значение, по умолчанию, границы, примеры, когда заработает |
| `/pn settings set <ключ> <значение>` | проверить, сохранить в `data/settings.json` и применить |
| `/pn settings reset <ключ>` | вернуть значение по умолчанию |
| `/pn settings pick <ключ> [часть названия]` | игрок: открыть в меню список значений настройки с выбором, только подходящие под часть названия |

Ключи и значения подсказываются по Tab. Если значение не подходит, ответ называет причину и допустимые границы, ничего не
меняется. Если изменение заработает только после перезапуска, ответ об этом говорит.

Типы значений:

- **вкл/выкл**: везде показывается как `включено` и `выключено` (в меню, в `/pn settings`, в `Настройки.txt`); вводить можно `вкл`, `выкл`, `включено`, `выключено`, `да`, `нет`, `true`, `false`, `on`, `off`;
- **число**: целое число в границах настройки;
- **время**: число с единицей, `30s`, `15m`, `6h`, `1h30m`, `2d` (подходят и `с`, `м`, `ч`, `д`);
- **текст**: всё, что написано после ключа, пробелы допустимы;
- **выбор из списка**: значение из длинного списка, например часовой пояс; в меню прокручивается кликом, команда принимает любое известное значение, Tab подставляет значения списка.

В меню переключатель меняется кликом, число кликом (левый больше, правый меньше, Shift на десять), текст и время вводятся в чате по
подсказке, колёсико возвращает значение по умолчанию. Если смотреть меню другого сервера или прокси, меняются его настройки.

У переключателя в подсказке два варианта, `включено` и `выключено`; тот, что стоит по умолчанию, помечен серым курсивом `(по умолчанию)`.
Отдельной строки «По умолчанию» у переключателя нет; у остальных настроек она появляется, только когда значение изменено.

### Выбор из длинного списка (часовой пояс)

В меню «Часовой пояс» работает как переключатель с прокруткой, такой же, как у настроек с вариантами в меню конфигов:

```
Часовой пояс
[ Значение ] Europe/Berlin
[ Вариант ] 3 из 21
[ Смещение ] UTC+01:00
[ Сейчас там ] 19:45
  · UTC
  · Europe/London
  ➤ Europe/Berlin
  · Europe/Kyiv
  ...
  ▼ ниже ещё 10
▸ Клик  следующий
▸ Правый клик  предыдущий
▸ Shift + клик  весь список
```

Клик записывает следующее значение (по кругу), правый клик предыдущее, окно из 8 строк идёт за текущим значением, строки
`▲ выше ещё N` и `▼ ниже ещё N` показывают, что скрыто. Крутится набор «Популярные» (`ChoiceSource.cycle`; у источника без такого набора
крутятся все значения). Если текущий пояс в набор не входит (например `Europe/Samara`), он стоит первой строкой окна со стрелкой, в строке
`Вариант` написано `— из 21`, а клик переходит к первому популярному (правый клик к последнему). Shift + клик открывает постраничный список
всех поясов (по 45 на странице); ввод в чате теперь только в нём. Колёсико возвращает значение по умолчанию, когда оно изменено.
В списке текущий пояс зелёный и не нажимается, клик по любому другому записывает его и возвращает к настройкам. Под каждым поясом написано,
что в нём сейчас, чтобы выбирать, не зная названия:

```
[ Смещение ] UTC+03:00
[ Сейчас там ] 21:45
```

Время идёт по 24-часовым часам, смещение берётся на сегодня, с учётом летнего времени (`UTC`, `UTC+03:00`, `UTC-05:00`).

Нижний ряд:

| Слот | Кнопка | Что делает |
|---|---|---|
| 46 | Ввести в чате | предлагает написать пояс точно (`/pn settings set time-zone …`) |
| 47 | Сортировка | клик переключает `по смещению UTC` (сначала по смещению, затем по названию; по умолчанию) и `по алфавиту` |
| 51 | Популярные | клик переключает `Все` и `Популярные`: UTC, Лондон, Берлин, Киев, Минск, Москва, Стамбул, Дубай, Ташкент, Алма-Ата, Дели, Бангкок, Шанхай, Токио, Сидней, Окленд, Сан-Паулу и четыре пояса США; при поиске вместо неё «Сбросить поиск» |
| 52 | Поиск | клик просит в чате часть названия; колёсико сбрасывает поиск |

Выбранные порядок и набор сохраняются при листании страниц. Для популярных порядок задан списком, поэтому кнопка сортировки там скрыта.

**Поиск.** Команда `/pn settings pick <ключ> [часть названия]` (только игрок, право `pnlibrary.settings`) открывает список настройки, уже сужённый до поясов,
в названии которых есть эта часть; регистр и различие между `_`, `/` и пробелом не важны, поэтому `/pn settings pick time-zone new york` найдёт `America/New_York`.
Заголовок показывает запрос, кнопка «Сбросить поиск» возвращает весь список; если ничего нет, написано «Ничего не найдено». Tab подсказывает ключи настроек с таким списком.

Список поясов строится на самом сервере или клиенте меню из `ZoneId.getAvailableZoneIds()`: региональные id (`Europe/Moscow`, `America/New_York`)
и `UTC`; устаревшие псевдонимы (`US/Pacific`, `SystemV/…`) и ряд `Etc/GMT±N` не показываются. По сети передаётся только имя списка, поэтому выбор работает и в меню
прокси. Команда `/pn settings set time-zone` по-прежнему принимает любой id, который знает Java, а Tab подсказывает пояса из списка.

Любую другую настройку можно сделать выбором из списка: в `SettingsRegistry` у неё тип `CHOICE` и список `ChoiceSource` (значения, способы сортировки,
необязательные популярные значения и строки «что это» для каждого значения).

## Настройки

| Ключ | Тип, границы | По умолчанию | Заработает | Что делает |
| --- | --- | --- | --- | --- |
| `privacy` | вкл/выкл | выкл | после перезапуска | Скрывать в диагностическом отчёте имена, UUID, адреса, пинг игроков и названия текущих серверов. |
| `history-retention-days` | число, 30–365 | 30 | после перезапуска | Сколько дней хранить историю диагностики. |
| `journal-foreign-plugins` | вкл/выкл | выкл | после перезапуска | Писать ли в журнал предупреждения и ошибки плагинов, не подключённых к pnLibrary. |
| `time-zone` | выбор из списка, id часового пояса | пояс сервера | сразу | Часовой пояс всех времён, которые показывает pnLibrary. Время хранится в UTC, смена пояса ничего не портит. Примеры: `UTC`, `Europe/Moscow`. |
| `no-permission-message` | текст, до 256 символов | Недостаточно прав для этой команды. | после перезапуска | Что видит игрок без права на команду pnLibrary или другого плагина, у которого нет своего сообщения. |
| `downloads.enabled` | вкл/выкл | вкл | сразу | Система загрузок. Выключена: все запросы плагинов на загрузку отклоняются. |
| `downloads.automatic` | вкл/выкл | вкл | сразу | Загрузки, которые плагин запускает сам, без команды (в том числе недостающие плагины). Тот же выбор делает `/pn deps auto on\|off` и переключатель в меню. |
| `updates.check-interval` | время, 15 минут – 7 дней | 6ч | после перезапуска | Как часто опрашивать каталоги релизов; первая проверка идёт при запуске. |
| `updates.restart.auto` | вкл/выкл | выкл | сразу | Перезапустить сервер самой, когда игроков не больше `updates.restart.max-players` столько времени, сколько задано в `updates.restart.quiet-time`. Не раньше 10 минут после запуска и не после отката (тогда сообщение с кнопками). Прокси сами не перезапускаются. |
| `updates.restart.max-players` | число, 0–200 | 0 | сразу | Сколько игроков ещё считается «мало»: для автоперезапуска и для кнопки «когда игроков не больше N». |
| `updates.restart.quiet-time` | время, 10 с – 1 час | 2м | сразу | Сколько времени подряд игроков должно быть не больше `updates.restart.max-players`, чтобы сервер перезапустился. |

Остальное (куда можно сохранять скачанные файлы (папка плагина и кэш), ожидание соединения и данных при скачивании обновления, интервал напоминаний об обновлениях, размер файла обновления, обязательная проверка SHA-256, содержимое отчёта,
сроки хранения отчётов) задано в коде и не настраивается. Интервал напоминаний читают отдельно Bukkit и оба прокси, размер файла
и проверка SHA-256 защищают безопасность.

Канал и пауза обновлений каждого плагина настраиваются отдельно: `/pn updates set`, см.
[updates.md](updates.md).

## Переход со старых версий

Если при запуске найдены `config.yml` или `downloads.yml` (старые версии), их значения один раз переносятся в `data/settings.json`,
файлы переименовываются в `config.yml.old` и `downloads.yml.old`, а в консоли появляется сообщение. Выбор автозагрузки,
сделанный раньше командой `/pn deps auto` (`data/downloads/preferences.state`), главнее `downloads.yml`. Ключи, которых больше нет
(например `excluded-paths`), пропускаются с предупреждением; убранные настройки загрузок и ожидания скачивания пропускаются молча. Уже заданное командой не перезаписывается старым файлом.

## Команды и права

Все права по умолчанию выдаются операторам; назначайте их в LuckPerms или другом менеджере прав. Полный список со всеми подкомандами лежит
и в файле `Команды.txt` в папке плагина; он строится из одного списка в коде (`LibraryCommandGuide`), а тест сверяет его с `plugin.yml`.

| Команда | Право | Что даёт |
| --- | --- | --- |
| `/pn`, меню `/pn gui` | `pnlibrary.admin` | управление библиотекой |
| `/pn status`, `/pn check` | `pnlibrary.updates.view` | состояние обновлений и проверка |
| `/pn updates ...` | `pnlibrary.updates.view` | каталог плагинов и история обновлений |
| `/pn updates set` | `pnlibrary.updates.settings` | канал и пауза плагина |
| `/pn update ...` | `pnlibrary.updates.download` | скачать и проверить обновление; подтвердить чувствительное действие |
| `/pn update restart` | `pnlibrary.updates.restart` | перезапуск после подготовки обновления |
| `/pn update rollback` | `pnlibrary.updates.rollback` | резервные копии и откат |
| установка новых компонентов | `pnlibrary.updates.install` | разрешает ставить новые компоненты |
| уведомления об обновлениях | `pnlibrary.updates.notify` | сообщения в чат при входе и по таймеру |
| `/pn events` | `pnlibrary.events.view` | журнал событий и ошибок |
| `/pn bus` | `pnlibrary.events.bus` | события плагинов: слушатели, вызовы |
| `/pn tasks` | `pnlibrary.tasks` | задачи плагинов, отмена |
| `/pn deps` | `pnlibrary.deps` | недостающие плагины, установка по коду |
| `/pn stats` | `pnlibrary.stats` | сводная статистика |
| `/pn placeholders` | `pnlibrary.placeholders` | плейсхолдеры (`info <адрес>`: как писать) |
| `/pn actions` | `pnlibrary.actions` | именованные действия, требования и функции |
| `/pn registry` | `pnlibrary.registry` | один список для всех реестров: `/pn registry <вид>`, `/pn registry find <текст>` |
| `/pn cooldowns` | `pnlibrary.cooldowns` | кулдауны игрока по всем плагинам, `clear` сбрасывает |
| `/pn downloads` | `pnlibrary.downloads` | объявленные загрузки и их состояние, `now` запускает |
| `/pn debug` | `pnlibrary.debug` | зашифрованный отчёт для поддержки |
| `/pn settings` | `pnlibrary.settings` | настройки библиотеки |
| `/pn configs` | `pnlibrary.configs` | конфигурации плагинов; менять: `pnlibrary.configs.edit` |
| `/pn groups` | `pnlibrary.groups` | группы серверов сети |
| `/pn servers` | `pnlibrary.servers` | серверы сети и удалённые действия |
| `/pn notices` | `pnlibrary.updates.restart` | важные объявления сети: кому нужен перезапуск |
| `/pn money list` | `pnlibrary.currency.list` | список валют |

Диагностический отчёт собирает сведения о сервере и плагинах, чтобы упростить поддержку. Он всегда сохраняется на сервере и
отправляется только в зашифрованном виде; в него всегда входят конфигурации плагинов (секретные значения скрываются) и последние
записи журнала.
