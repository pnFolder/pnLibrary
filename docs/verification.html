2. Обновление самой pnLibrary

Нужно, чтобы на сервере стояла версия старее той, что в каталоге. В каталоге на GitHub сейчас лежит 0.0.1-dev.5, значит ставим 0.0.1-dev.4.

Собрать «старую» версию 0.0.1-dev.4 и поставить›

Что сделать

  1. Останови Paper-Standalone.
  2. Собери старую версию: 
    ./gradlew :distribution:shadowUniversal -Pversion=0.0.1-dev.4
  3. Удали из Paper-Standalone\plugins файл dev.5 и положи туда distribution\build\libs\pnLibrary-0.0.1-dev.4-universal.jar.
  4. Если Gradle не принял -Pversion: временно поменяй version= в gradle.properties на 0.0.1-dev.4, собери, потом верни 0.0.1-dev.5 и пересобери. Не коммить эту правку.
  5. Запусти сервер. В баннере должна быть 0.0.1-dev.4.

Ожидаем

Сервер стартует на dev.4.

Если не так

В баннере dev.5: значит собралась не старая версия. Проверь имя файла в distribution\build\libs.
Проверка видит новую версию›

Что сделать

  1. Консоль: pn check
  2. Затем: pn updates info pnlibrary

Ожидаем

В списке у pnLibrary доступна 0.0.1-dev.5. В карточке видны версия, канал (dev), API, Java, ссылки.

Если не так

«Каталог не найден»: в сообщении будет полный адрес releases.json. Открой его в браузере. Нет сети или GitHub недоступен.
Подготовка обновления: jar на ходу не заменяется›

Что сделать

  1. Консоль: pn update pnlibrary
  2. Потом: pn update status
  3. Посмотри папку plugins\pnLibrary\updates\transactions и то, что в plugins лежит всё ещё dev.4.

Ожидаем

Статус «подготовлено», появилась папка транзакции. Рабочий jar в plugins не изменился. Сервер сам не перезапустился.

Если не так

Если jar в plugins подменился на ходу, это ошибка: главное правило нарушено.
Код подтверждения перезапуска›

Что сделать

  1. pn update restart — в ответ придёт код.
  2. Введи неправильный код: pn update confirm 000000. Должен отклонить.
  3. Подожди 30 секунд и введи настоящий код. Должен отклонить как просроченный.
  4. Запроси новый код и сразу подтверди: pn update confirm <код>.
  5. Если запускал из игры, код игрока не должен подойти в консоли и наоборот.

Ожидаем

Чужой, неверный и просроченный код отклоняются понятным сообщением. Правильный принимается один раз.

Если не так

Старый или чужой код сработал: это ошибка безопасности.
После ручного перезапуска сервер на dev.5›

Что сделать

  1. Останови сервер сам (stop) и запусти снова.
  2. Если версия осталась dev.4: подготовленные файлы применяет установщик при остановленном сервере. Останови сервер и выполни (имя jar уточни в distribution\build\libs): 
    java -jar pnLibrary-updater-0.0.1-dev.5.jar --server-stopped plugins/pnLibrary
    Запускай из папки сервера. Потом запусти сервер.
  3. В консоли: pn updates history

Ожидаем

Баннер 0.0.1-dev.5. В истории запись о переходе dev.4 → dev.5 с итогом «успешно».

Если не так

Запиши, применилось ли обновление само при старте или только через установщик, и пришли консоль. Это важно: от этого зависит, что писать в инструкции.
Пауза, канал и автозагрузка›

Что сделать

  1. Верни dev.4 (как в первом пункте этого раздела).
  2. pn updates set pnlibrary hold 1m, потом pn update pnlibrary.
  3. Через минуту повтори pn update pnlibrary.
  4. pn updates set pnlibrary channel stable, потом pn updates info pnlibrary. Верни dev.
  5. Открой plugins\pnLibrary\updates.yml: library.automatic-download поставь false, перезапусти, сделай pn check. Файл не заменяй целиком.

Ожидаем

Во время паузы подготовка отклонена с причиной «пауза». Через минуту пауза снялась сама. Канал stable прячет dev-версии. При automatic-download: false версия сама не готовится, при true готовится после check.

Если не так

Пауза не снялась или канал не влияет — запиши.

Если не так

Новая версия не запустилась → автоматический откат›

Что сделать

  1. Подготовь обновление как в разделе 2.
  2. Перед применением испорти подготовленный jar (поменяй один байт в файле внутри updates\transactions\<id>) только в тестовой копии сервера.

Если не так

Повреждённый jar был установлен без проверки — серьёзная ошибка.
Установщик не работает при живом сервере›

Что сделать

  2. Попробуй запустить установщик из раздела 2 при работающем сервере.

Ожидаем

Установщик отказывается из-за файла install.lock.

Если не так

Установщик начал менять файлы при живом сервере — ошибка.

4. Тестовый каталог для плагина

Обновления плагинов читают список версий из GitHub (.pnlibrary/releases.json), поэтому для проверки «плохих» плагинов нужен свой тестовый репозиторий. Подопытным будет приёмочный плагин pnLibraryAcceptance из папки examples/acceptance-bukkit: он уже умеет читать каталог из любого репозитория через свой config.yml. Делается один раз, потом ты только меняешь releases.json.

Создать тестовый репозиторий и выложить jar›

Что сделать

  1. На GitHub создай публичный репозиторий, например pn-catalog-test (под своим аккаунтом, не в pnFolder).
  2. Собери приёмочный плагин: 
    ./gradlew :examples:acceptance-bukkit:jar
Get-ChildItem examples\acceptance-bukkit\build\libs
    Имя файла будет вида pnLibrary-acceptance-0.0.1-dev.5-bukkit-java8.jar.
  3. Скопируй этот jar в Paper-Standalone\plugins как «установленную» версию (рядом с pnLibrary).
  4. Для «новой» версии пересобери с другим номером и переименуй: 
    ./gradlew :examples:acceptance-bukkit:jar -Pversion=0.1.0-stable.1
Get-ChildItem examples\acceptance-bukkit\build\libs
    Вернись к обычной сборке потом: ./gradlew :distribution:shadowUniversal (версия в gradle.properties остаётся dev.5).
  5. На GitHub в тестовом репозитории: Releases → Draft a new release → тег v0.1.0-stable.1 → прикрепи этот jar → Publish.
  6. Посчитай хеш этого же файла: 
    Get-FileHash .\pnLibrary-acceptance-0.1.0-stable.1-bukkit-java8.jar -Algorithm SHA256
  7. В репозитории создай файл .pnlibrary/releases.json в ветке main по образцу ниже (подставь свой ник, хеш и размер файла в байтах: (Get-Item файл).Length).

Образец releases.json (нормальная версия)

{
  "schema": 1,
  "product": "pnlibraryacceptance",
  "releases": [
    {
      "version": "0.1.0-stable.1",
      "channel": "stable",
      "description": "Тестовая версия для проверки обновлений.",
      "publishedAt": "2026-10-31T12:00:00Z",
      "api": { "minimum": 1, "maximum": 1 },
      "artifacts": [
        {
          "file": "pnLibrary-acceptance-0.1.0-stable.1-bukkit-java8.jar",
          "platform": "BUKKIT",
          "java": { "minimum": 8 },
          "url": "https://github.com/ТВОЙ_НИК/pn-catalog-test/releases/download/v0.1.0-stable.1/pnLibrary-acceptance-0.1.0-stable.1-bukkit-java8.jar",
          "sha256": "ВСТАВЬ_ХЕШ_64_СИМВОЛА",
          "size": 12345
        }
      ]
    }
  ]
}
id продукта. Поле product должно совпадать с id, под которым плагин зарегистрирован. Узнай его так: запусти сервер с приёмочным плагином и введи pn updates list — id виден в списке и в pn updates info <имя>. Если id другой, поправь product.
Каталог читается с ветки main. После правки releases.json нужно закоммитить в main. GitHub может отдавать старую копию до нескольких минут: если изменение не видно, подожди и повтори pn check.

Настройка приёмочного плагина

Останови сервер, запусти его один раз, чтобы создался plugins\pnLibraryAcceptance\config.yml, и поправь блок updates:

updates:
  enabled: true
  channel: STABLE
  repository-owner: ТВОЙ_НИК
  repository-name: pn-catalog-test
  artifact-pattern: '(?i)^pnLibrary-acceptance-.*-bukkit-java8\.jar$'

Перезапусти сервер, потом в консоли: pnaccept update и pn check.

Ожидаем

В pn у pnLibraryAcceptance доступна версия 0.1.0-stable.1. pn update pnlibraryacceptance (используй имя из списка) скачивает файл, сверяет хеш и готовит обновление.

Если не так

Плагин не виден в списке: проверь updates.enabled: true и что jar приёмочного плагина лежит в plugins. Каталог не найден: открой адрес из сообщения в браузере, он должен показывать твой JSON.

5. Плохие плагины: что должно блокироваться

Для каждого пункта меняешь releases.json в тестовом репозитории (или конфиг), коммитишь в main, делаешь pn check и смотришь pn updates info <плагин> и pn update status. После пункта возвращай файл к нормальному виду.

Неверная контрольная сумма›

Что сделать

  1. В sha256 замени несколько символов.
  2. pn check, затем pn update <плагин>.
  3. Посмотри plugins\pnLibrary\updates.

Ожидаем

Подготовка отклонена, сообщение про несовпадение суммы. Файл в рабочую папку не попал, недокачанных файлов нет.

Если не так

Файл всё же подготовлен — серьёзная ошибка проверки целостности.
Нет контрольной суммы›

Что сделать

  1. Удали строку "sha256" из артефакта (и запятую перед ней).
  2. pn check и pn update <плагин>.

Ожидаем

Подготовка отклонена: сумма обязательна (require-sha256 включён по умолчанию).

Если не так

Установилось без суммы — ошибка.
Размер файла не совпал›

Что сделать

  1. В size поставь число на 100 больше настоящего.
  2. pn update <плагин>.

Ожидаем

Подготовка отклонена из-за размера.

Если не так

Приняло файл — запиши.
Плагину нужна другая версия API pnLibrary›

Что сделать

  1. У релиза поставь "api": { "minimum": 2, "maximum": 2 } (сейчас API библиотеки равно 1).
  2. pn check, затем pn updates info <плагин>, pn update status.
  3. Открой меню /pn gui и найди этот плагин.

Ожидаем

Релиз заблокирован: причина «несовместимое API» или «нет подходящего релиза», в сообщении видны нужный и поддерживаемый диапазоны. Когда библиотека слишком старая для плагина, есть подсказка сначала обновить pnLibrary. Остальные плагины не страдают.

Если не так

Обновление молча проигнорировано без причины или, наоборот, подготовлено.
Обратный случай (плагин поддерживает только старое API, а библиотека новее) воспроизвести сейчас нельзя, пока не выйдет API 2. Он покрыт автотестами.
Нужна более новая Java›

Что сделать

  1. У артефакта поставь "java": { "minimum": 99 }.
  2. pn check, pn updates info <плагин>.

Ожидаем

Нет подходящего файла для этой Java, подготовка отклонена с понятной причиной.

Если не так

Подготовлен файл для несовместимой Java.
Файл для другой платформы›

Что сделать

  1. У артефакта поставь "platform": "VELOCITY" (а сервер у тебя Bukkit).
  2. pn check, pn updates info <плагин>.

Ожидаем

Для этой платформы файла нет, обновление не готовится.

Если не так

Подготовился чужой файл.
Ссылка не HTTPS и битый JSON›

Что сделать

  1. В url замени https:// на http://, сделай pn check.
  2. Верни. Потом сломай JSON (убери закрывающую скобку), снова pn check.

Ожидаем

В обоих случаях каталог отклонён, в сообщении путь к полю (например releases[0].artifacts[0].url) или полный адрес каталога. Сервер не падает, рабочие плагины не затронуты.

Если не так

Исключение в консоли вместо понятного сообщения.
Нужен сторонний плагин, которого нет›

Что сделать

Если не так

Блокировки нет или нет ссылки.
Верни dependency.enabled: false после проверки.
Пауза и игнорирование плагина›

Что сделать

  1. pn updates set <плагин> hold on, pn update <плагин> — должно блокироваться (пауза 7 дней). Снять: hold off.
  2. В plugins\pnLibrary\updates.yml в plugins.ignored добавь id плагина строчными. Перезапусти. pn check.

Ожидаем

При паузе причина «пауза». Игнорируемый плагин не обновляется никогда. Остальные плагины в плане обновляются как обычно.

Если не так

Плагин обновился несмотря на паузу или игнор.
Установка нового плагина, которого на сервере нет›

Что сделать

  1. Убери приёмочный плагин из plugins нельзя (он же и регистрирует обновления), поэтому проверь через конфиг: в updates.yml installation.allow-new-plugins: false.
  2. Посмотри, что pn updates available не предлагает ставить то, чего нет. Потом поставь true, перезапусти и повтори.

Ожидаем

При false новые плагины не ставятся, при true ставятся с подтверждением.

Если не так

Новый плагин поставился при false.
Этот сценарий требует плагин, который есть в каталоге, но не установлен. Если такого у тебя нет, пропусти и отметь в заметке «не проверялось».
Зарезервированные имена плагина›

Что сделать

  1. Собери тестовый плагин с именем confirm (или status, rollback, restart), который вызывает регистрацию обновлений.
  2. Запусти.

Ожидаем

Регистрация обновлений отклонена с понятным сообщением в консоли.

Если не так

Плагин зарегистрировался и команда /pn update confirm стала конфликтовать.
Это самый трудозатратный сценарий. Он покрыт автотестами, ручную проверку можно пропустить.

6. Прокси и игровой сервер

Проверяется связка Velocity + Velocity\Backend и отдельно BungeeCord + BungeeCord\Backend. Повтори каждый пункт для обеих пар. Связь работает только пока на игровом сервере есть игрок онлайн.

Папки с ключом.
Velocity (прокси): C:\Users\lpvan\Downloads\Server\Velocity\plugins\pnlibrary\link.key (папка с маленькой буквы).
Velocity (игровой): C:\Users\lpvan\Downloads\Server\Velocity\Backend\plugins\pnLibrary\link.key (с большой L).
BungeeCord (прокси): C:\Users\lpvan\Downloads\Server\BungeeCord\plugins\pnLibrary\link.key.
BungeeCord (игровой): C:\Users\lpvan\Downloads\Server\BungeeCord\Backend\plugins\pnLibrary\link.key.
Ключ создаёт только прокси. Игровой сервер файл только читает.
Ключ связи: создать и скопировать›

Что сделать

  1. Останови игровой сервер (Backend).
  2. Запусти прокси. Проверь, что файл link.key появился в папке прокси.
  3. Скопируй ключ на игровой сервер (Velocity): 
    New-Item -ItemType Directory -Force "C:\Users\lpvan\Downloads\Server\Velocity\Backend\plugins\pnLibrary" | Out-Null
Copy-Item "C:\Users\lpvan\Downloads\Server\Velocity\plugins\pnlibrary\link.key" "C:\Users\lpvan\Downloads\Server\Velocity\Backend\plugins\pnLibrary\link.key" -Force
  4. То же для BungeeCord: 
    New-Item -ItemType Directory -Force "C:\Users\lpvan\Downloads\Server\BungeeCord\Backend\plugins\pnLibrary" | Out-Null
Copy-Item "C:\Users\lpvan\Downloads\Server\BungeeCord\plugins\pnLibrary\link.key" "C:\Users\lpvan\Downloads\Server\BungeeCord\Backend\plugins\pnLibrary\link.key" -Force
  5. Убедись, что файлы одинаковые: 
    Get-FileHash "C:\Users\lpvan\Downloads\Server\Velocity\plugins\pnlibrary\link.key","C:\Users\lpvan\Downloads\Server\Velocity\Backend\plugins\pnLibrary\link.key" -Algorithm MD5 | Select-Object Hash,Path
Get-FileHash "C:\Users\lpvan\Downloads\Server\BungeeCord\plugins\pnLibrary\link.key","C:\Users\lpvan\Downloads\Server\BungeeCord\Backend\plugins\pnLibrary\link.key" -Algorithm MD5 | Select-Object Hash,Path
  6. Запусти игровой сервер.

Ожидаем

Два хеша в каждой паре одинаковые. Игровой сервер запустился без ошибок про ключ.

Если не так

Хеши разные — скопируй заново. Файл в формате «одна строка base64, не меньше 32 байт»; повреждённый файл отключает связь.
Карта сети дошла, иконка «Сеть» видна›

Что сделать

  1. Зайди игроком (оператором) на сервер через прокси.
  2. Подожди 30–40 секунд.
  3. На игровом сервере: /pn gui → иконка «Сеть».
  4. На игровом сервере: /pn servers.
  5. На прокси в консоли: pnproxy servers (или короткое pnp servers).

Ожидаем

В меню есть «Сеть», внутри видны прокси и серверы с плагинами и состоянием обновлений. Прокси показывает игровой сервер, версию pnLibrary и игроков.

Если не так

Иконки «Сеть» нет совсем: нет link.key на игровом сервере или он битый.
Иконка есть, но в подсказке «данные ещё не пришли»: подожди ещё 30 секунд, проверь, что игрок реально онлайн, и что ключи одинаковые.
Ничего не приходит: сравни хеши ключей (пункт выше).
Без игрока связь молчит (это нормально)›

Что сделать

  1. Выйди со всех серверов, подожди минуту.
  2. Из консоли игрового сервера: pn servers — данные могут быть старые.
  3. Зайди снова и подожди полминуты.

Ожидаем

Без игрока новые данные не приходят и ошибок нет. С игроком карта обновляется.

Если не так

Ошибки в консоли, когда на сервере нет игроков.
Ключи разные — сообщения отбрасываются без шума›

Что сделать

  1. Останови игровой сервер.
  2. В его link.key поменяй один символ (сохрани копию ключа заранее).
  3. Запусти, зайди игроком, подожди минуту.
  4. Верни правильный ключ и перезапусти.

Ожидаем

Карта сети не приходит, но в консоли нет ошибок и спама. После возврата ключа связь возвращается.

Если не так

Сервер падает или сыплет исключениями при неправильном ключе.
Удалили папку на прокси → новый ключ›

Что сделать

  1. Остановить прокси и игровой сервер.
  2. Удали папку pnLibrary на прокси (сначала сохрани копию рядом, например pnlibrary.bak, чтобы не потерять данные).
  3. Запусти прокси: появился новый link.key.
  4. Запусти игровой сервер со старым ключом, зайди, подожди минуту — связи быть не должно.
  5. Скопируй новый ключ на игровой сервер, перезапусти — связь вернулась.

Ожидаем

Ключ создаётся заново, старый не работает, новый возвращает связь. Группы (groups.tsv) в удалённой папке тоже пропали.

Если не так

Ключ не создался или связь не вернулась после копирования.
Управление другим сервером›

Что сделать

  1. Нужен игрок на сервере, с которого спрашиваешь. С игрового сервера: /pn servers <имя другого сервера> check.
  2. Попробуй /pn servers <имя> update <плагин> и /pn servers <имя> auto <плагин> on.
  3. То же кнопками в меню «Сеть» → сервер.
  4. Попробуй без нужного права (pnlibrary.updates.view / .download / .settings).

Ожидаем

Другой сервер выполняет проверку, скачивание или смену автозагрузки и отвечает. Без права запрос не уходит. Ничего кроме этих трёх действий отправить нельзя. Меню другого сервера открывается у тебя на экране.

Если не так

Ответ не приходит: проверь, что на спрашивающем сервере есть игрок, ключи совпадают, имя сервера написано как в списке.
Прокси: команды и права›

Что сделать

  1. В консоли прокси: pnproxy, pnp, pnproxy servers, pnproxy update check, pnproxy update status.
  2. Всё, что меняет что-то, должно работать только из консоли прокси. Попробуй от игрока на прокси.

Ожидаем

Команды отвечают, подсказки используют имя /pnproxy. Изменяющие действия игроком недоступны.

Если не так

Подсказки предлагают /pn вместо /pnproxy на прокси, или игрок смог менять.

7. Группы серверов

Команды на прокси начинаются с pnproxy groups …, на игровом сервере с /pn groups …. Нужна работающая связь из раздела 6. Правки нужно право pnlibrary.groups.

Создать группу и наполнить›

Что сделать

  1. На прокси (замени lobby и backend на реальные имена; имена серверов смотри в pnproxy servers): 
    pnproxy groups create lobby
pnproxy groups join lobby backend
pnproxy groups require lobby pnLibrary
pnproxy groups info lobby
pnproxy groups
  2. Проверка имени-команды: pnproxy groups create create — должна создаться группа с именем «create».

Ожидаем

Группа создана, сервер добавлен, в info видно, чего не хватает и что можно обновить. Сообщения оформлены в стиле библиотеки, а при неполной команде под строкой «Использование» есть описание.

Если не так

Сырой текст ошибки или команда не принимает имя группы create.
Отличия сервера: skip, extra, reset, of›

Что сделать

pnproxy groups skip lobby backend pnLibrary
pnproxy groups server lobby backend
pnproxy groups extra lobby backend SomePlugin
pnproxy groups of backend
pnproxy groups reset lobby backend
pnproxy groups server lobby backend

Ожидаем

После skip группа не ждёт плагин от этого сервера (сам плагин остаётся включённым). extra добавляет лишнее требование. reset возвращает сервер «как все». of показывает все группы сервера.

Если не так

Отличие не применилось или применилось к другим серверам группы.
Сервер в нескольких группах и прокси как участник›

Что сделать

pnproxy groups create survival
pnproxy groups join survival backend
pnproxy groups join lobby @proxy
pnproxy groups of backend
pnproxy groups of @proxy

Ожидаем

Сервер состоит в обеих группах. Прокси участвует под именем @proxy, оно не путается с сервером под названием «proxy».

Если не так

Сервер можно добавить только в одну группу или @proxy не принимается.
Меню Сеть → Группы›

Что сделать

  1. В игре на игровом сервере: /pn gui → Сеть → Группы.
  2. Создай группу кнопкой: она вставит команду в чат, допиши имя.
  3. Добавь сервер и плагин, кликни по серверу и посмотри его отличия.
  4. Удали группу кнопкой.
  5. Попробуй без права pnlibrary.groups.

Ожидаем

Меню строит сервер игрока, а прокси только отвечает. Без права правки закрыты. Изменения видны и в командах.

Если не так

Скриншот меню.
Группы хранятся в groups.tsv и переживают перезапуск›

Что сделать

  1. Открой groups.tsv рядом с link.key на прокси. Первая строка #pnlibrary-groups 2.
  2. Перезапусти прокси. Проверь pnproxy groups.
  3. Испорти одну строку в файле, перезапусти: нечитаемая строка пропускается, прокси не падает.

Ожидаем

Группы на месте после перезапуска. Битая строка не роняет прокси.

Если не так

Группы пропали или прокси упал на битой строке.

8. События, задачи и API для плагинов

Заход и выход игрока видны как события библиотеки›

Что сделать

  1. Зайди и выйди игроком на Paper-Standalone, потом через Velocity, потом через BungeeCord.
  2. На сервере: /pn bus и /pn bus history. На прокси: pnproxy bus.

Ожидаем

Событие PlayerJoinedEvent и PlayerLeftEvent считаются по одному разу на каждый заход и выход, на каждой платформе. В истории есть дни «Сегодня» и «Вчера».

Если не так

Событие приходит дважды или не приходит.
Приёмочный плагин: все подкоманды›

Что сделать

/pnaccept status
/pnaccept event
/pnaccept task
/pnaccept cooldown
/pnaccept metrics
/pnaccept update
/pnaccept download
/pnaccept diagnostics

Затем /pn events, /pn tasks.

Ожидаем

Каждая команда отвечает без ошибок. Событие, задача и счётчики видны в /pn bus и /pn tasks. download и часть остальных подсказывают включить опцию в config.yml, это нормально.

Если не так

Исключение в консоли.
Выключение плагина убирает его слушатели и задачи›

Что сделать

  1. /pnaccept event, затем /pn bus — виден слушатель приёмочного плагина.
  2. Выключи плагин (plugman или перезапуск без него) и снова /pn bus.

Ожидаем

После выключения слушателей и задач плагина нет.

Если не так

Слушатели остались — утечка.

9. Диагностика и данные

Отчёт /pn debug создаётся и расшифровывается›

Что сделать

  1. Консоль: pn debug (право pnlibrary.debug).
  2. Найди созданный файл отчёта (.pnsupport, путь будет в сообщении).
  3. Расшифруй: 
    python tools\support\decode_pnsupport.py ПУТЬ_К_ОТЧЁТУ
    Если скрипт просит другой формат аргументов, запусти его без аргументов: он покажет подсказку.

Ожидаем

Отчёт расшифровывается, внутри данные сервера и плагинов. Пути из excluded-paths и данные, скрытые в privacy, в отчёт не попали.

Если не так

Секретные данные видны в открытом виде — серьёзная ошибка приватности.
Журнал ошибок и сводка при входе›

Что сделать

  1. Вызови ошибку (например /pnaccept diagnostics, или сломай что-то заведомо, как в разделе 5).
  2. /pn events и /pn events error (уровень пишется строчными).
  3. Выйди и зайди оператором.

Ожидаем

Запись видна в журнале. При входе админ видит сводку (если включён journal-join-notice).

Если не так

Ошибка не записалась.
config.yml: ключи работают›

Что сделать

  1. Открой plugins\pnLibrary\config.yml. Ключи: privacy, excluded-paths, history-retention-days (от 30), journal-foreign-plugins, journal-join-notice, time-zone, no-permission-message.
  2. Поменяй time-zone (например Asia/Tokyo) и no-permission-message, перезапусти.
  3. Поставь history-retention-days: 1 — должно быть принято как минимум 30 или отклонено с понятным сообщением.

Ожидаем

Время в журнале в нужном поясе, сообщение об отсутствии прав новое. Значение ниже 30 не ломает запуск.

Если не так

Сервер не стартует из-за неверного значения.

10. Остановка и перезагрузка

Нормальная остановка всех серверов›

Что сделать

  1. На каждом из пяти серверов введи stop и дождись завершения.
  2. Прочитай конец консоли.

Ожидаем

Нет ошибок и предупреждений от pnLibrary, процесс завершается сам, а не висит.

Если не так

Процесс не завершается: запиши, какой сервер и что в консоли.
/reload и повторная загрузка›

Что сделать

  1. На Paper-Standalone: /pnaccept event, /pn bus.
  2. Выполни /reload confirm (или перезагрузи плагин менеджером), снова /pnaccept event, /pn bus.

Ожидаем

Слушатель и задачи не удвоились.

Если не так

Счётчики идут через два.
/reload официально не поддерживается Paper и может сломать посторонние плагины. Если сомневаешься, пропусти пункт и отметь в заметке.
Остановка во время скачивания не оставляет мусор›

Что сделать

  1. Запусти pn update <плагин> с большим файлом (или с отключённой сетью на середине).
  2. Сразу stop.
  3. Посмотри plugins\pnLibrary\updates и запусти сервер.

Ожидаем

Нет битых файлов. После запуска состояние чистое, обновление можно подготовить заново.

Если не так

Остался неполный файл, который мешает следующей подготовке.

Что эта проверка не покрывает: удалённые политики (remote-policy), нативные проверки на реальных серверах (:modules:updates:verifyNativeProxyUpdates, :modules:updates:verifyNativeBukkitUpdates, см. docs/updates.md), Folia, встроенный установщик PnLibraryBootstrap и публикацию в Maven Central.
