# Удалённые политики

Политика — один `.java`-файл по ссылке `https://` или `file:` (абсолютной), не больше 1 МБ. Класс в файле
реализует `RemotePolicy`, имеет публичный конструктор без аргументов и возвращает `RemotePolicyResult`
(`allow()`, `deny(текст)` или `allowing(...)`/`denying(...)` с карточкой: статус, заголовок, детали, шаги, ссылки).
Из контекста политика видит продукт, платформу, версию сервера и значения `values`, заданные плагином.

```java
public class ExamplePolicy implements RemotePolicy {
    public RemotePolicyResult check(RemotePolicyContext context) {
        if (context.getProduct().getVersion().startsWith("0.")) {
            return RemotePolicyResult.deny("Эта версия больше не поддерживается");
        }
        return RemotePolicyResult.allow();
    }
}
```

## Настройки

`RemotePolicySettings` задаёт плагин:

| Поле | По умолчанию | Смысл |
|---|---|---|
| `source` | обязательно | ссылка на `.java`-файл |
| `checkEvery` | 6 часов | как часто политика проверяется заново, не реже раза в минуту |
| `onDeny` | `DISABLE_PLUGIN` | что делать при отказе: `DISABLE_PLUGIN` или `DISABLE_MODULE` |
| `onError` | `DENY` | что делать, если политику не удалось проверить (нет сети, нет компилятора, битый файл): `DENY` считает это отказом, `DENY_UNTIL_CHECKED` не запускает плагин, пока не было ни одной успешной проверки, `KEEP_RUNNING` пишет предупреждение и продолжает |
| `supportUrl` | Discord pnFolder | куда отправить администратора, если плагин не запустился |
| `startupTimeout` | 20 секунд | сколько запуск плагина ждёт первую проверку |
| `values` | пусто | значения для политики |

Скачивание: таймаут соединения 8 секунд, чтения 30 секунд.

## Компиляция

Сервер компилирует файл своим javac. Если сервер запущен на JRE без компилятора, тот же загрузчик Libby, что берёт
Kotlin, при первой проверке политики докачивает компилятор ECJ в `libraries/pnlibrary` (3.43 для Java 17 и новее,
3.26 для старой Java), и политика компилируется им, поэтому JDK не нужен. Если докачать не удалось, проверка
политики сообщает об этом, дальше действует `onError`. Политика всегда собирается под Java 8 и работает на любой
Java. Сервер с javac ничего не скачивает.

## Безопасность

Исполняемые политики — доверенный код с полномочиями JVM сервера. ClassLoader не является
песочницей. Защита политики — доступ к репозиторию, где она лежит: храните её в репозитории с ограниченной записью.

Встроенная бизнес-политика pnLibrary сохраняет своё прежнее поведение и Java-реализацию.
Неизвестный или недоверенный исполняемый код требует отдельного процесса с ограничением времени
и полномочий; этот механизм не предназначен для его безопасного запуска внутри сервера.
